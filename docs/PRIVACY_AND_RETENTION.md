# الخصوصية والاحتفاظ بالبيانات

هذه سياسة تشغيل هندسية وليست نصاً قانونياً نهائياً. يجب اعتماد صفحات الخصوصية وشروط الاستخدام من مستشار قانوني في الدول المستهدفة.

## تقليل البيانات

- اجمع ما يلزم للعقد، الإدارة، الفوترة والالتزام فقط.
- لا تُظهر الصفحة العامة اسم المالك، بيانات المستأجر، رقم الوحدة الداخلي، مستندات الملكية، العقد أو حالة المديونية.
- روابط الوثائق مؤقتة وموقعة ومقيدة بالغرض. مشاركة فاتورة عامة تستخدم token عشوائياً يخزن hash وتعرض merchant، رقم/تاريخ/إجمالي/حالة فقط، من دون عنوان كامل أو هاتف أو line metadata حساس.
- logs تحتوي IDs/correlation لا email/phone/token/body. Sentry/telemetry scrub قبل الإرسال.

## تصنيف واحتفاظ افتراضي

| الفئة                 | التصنيف     | الاحتفاظ الافتراضي                       |
| --------------------- | ----------- | ---------------------------------------- |
| الجلسات وreset tokens | سري         | حتى الانتهاء + 30 يوماً للأدلة المختصرة  |
| audit الأمني          | مقيد        | 1–2 سنة حسب السياسة، append-only         |
| العقود والتواقيع      | مقيد/قانوني | مدة العقد + المدة القانونية المعتمدة     |
| الفواتير/ledger       | مالي        | المدة النظامية المعتمدة لكل دولة         |
| صور العقار العامة     | عام         | حتى إلغاء النشر ثم purge من CDN خلال SLA |
| أصول الصور الخاصة     | داخلي       | عمر العقار/الحساب وفق العقد              |
| بلاغات الصيانة        | داخلي/شخصي  | عمر الإيجار + مدة النزاع                 |
| raw webhooks          | سري         | أقصر مدة للتسوية/النزاع مع redaction     |
| application logs      | داخلي       | 30–90 يوماً                              |
| backups               | مقيد        | سياسة GFS مشفرة، ثم حذف تلقائي           |

لا تُثبّت المدد قبل قرار قانوني. يجب أن تكون المدة configuration موثقة لا SQL متناثراً.

## طلبات أصحاب البيانات

عملية access/export/correction/deletion تحتاج تحقق هوية وapproval وسجل audit. الحذف logical أولاً عند وجود التزام قانوني، ثم purge بعد انتهاء hold. عند الحذف:

1. ألغِ الروابط والجلسات والمفاتيح.
2. احذف/عمِّ البيانات غير الملزمة قانونياً.
3. أبقِ الحد الأدنى المالي أو القانوني مع restriction marker.
4. schedule حذف S3/CDN/search/cache.
5. اترك tombstone غير شخصي لمنع resurrection من event قديم.
6. ستنتهي النسخة من backups عبر دورة retention؛ لا تعدل backup ثابتاً يدوياً.

## مواقع البيانات والموردون

سجل data flow وموقع PostgreSQL/S3/backup/telemetry والبريد لكل بيئة. أي نقل عبر الحدود أو subprocessor جديد يحتاج DPIA/مراجعة تعاقدية. الإنتاج لا يستخدم Mailpit/MinIO المحليين.
