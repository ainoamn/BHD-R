# حماية BHD R من الاحتيال والاختراق

**الجمهور:** مالك المنصة، مفوّضو تحكم الموقع، فريق التشغيل.  
**الواجهة:** [تحكم الموقع → الأمن والتدقيق](https://r.bhd-om.com/ar/admin/security)  
**آخر تحديث:** 2026-10-29

---

## 1. ماذا نحمي؟

| الأصل                          | الضابط                                                 |
| ------------------------------ | ------------------------------------------------------ |
| جلسات المنتج (`bhd_r_session`) | بصمة IP + وكيل + رمز دولة عند الإصدار؛ إلغاء عند القفل |
| حسابات المستخدمين              | قفل أمني بعد تكرار فشل موجّه لنفس البريد               |
| عناوين IP المسيئة              | حجر مؤقت تلقائي أو يدوي من لوحة الأمن                  |
| سجلات التدقيق                  | أحداث `security.*` + سجل محاولات الدخول                |
| استعادة الحساب                 | هوية مدنية + آخر معاملة + OTP بريد (واتساب لاحقاً)     |

كلمات المرور تُدار عبر **BHD Identity** (`id.bhd-om.com`). المنتج يستقبل إشارات الفشل عبر `/api/internal/security/auth-signal` ويطبّق الحجر/القفل هنا.

---

## 2. لوحة الأمن والتدقيق

المسار: `/ar/admin` → **الأمن والتدقيق**.

| تبويب            | الوظيفة                                                                      |
| ---------------- | ---------------------------------------------------------------------------- |
| التهديدات والفحص | فحص آلي بقواعد (اندفاع فشل IP، اشتباه سرقة حساب، دول متعددة، أقفال/حجر نشطة) |
| الجلسات والدول   | من أي دولة دخل المستخدمون، وبأي حساب (بريد/اسم)                              |
| محاولات الدخول   | IP خام + الدولة + النتيجة + السبب (لعمليات الاحتيال)                         |
| حجر IP           | قائمة نشطة + حجر يدوي + إطلاق                                                |
| الحسابات المقفلة | فتح يدوي أو توجيه المالك إلى `/security-unlock`                              |
| التدقيق          | آخر أحداث `audit_logs` وأكثر الإجراءات                                       |

البحث يعمل عبر IP / الدولة / البريد / بصمة الهاش حسب التبويب.

---

## 3. حجر عنوان IP (احتراز)

### متى يحدث تلقائياً؟

- خلال **15 دقيقة**: ≥ **8** محاولات فاشلة أو محظورة من نفس بصمة IP.
- المدة الافتراضية: **ساعتان**.
- أثناء الحجر: رفض إصدار جلسة منتج جديدة من ذلك العنوان (`bhd=ip_quarantined`).

### يدوياً

من تبويب **حجر IP**: أدخل العنوان → **حجر الآن**. يمكن الإطلاق قبل انتهاء المدة.

### مصدر الإشارات

1. فشل/نجاح مسار OAuth للمنتج (`/api/auth/bhd/callback`).
2. محاولات استعادة القفل الخاطئة (`/api/security/unlock/*`).
3. إشارات Identity عبر `POST /api/internal/security/auth-signal` (Bearer `INTERNAL_SECURITY_SECRET` أو `CRON_SECRET`).

---

## 4. قفل الحساب بعد محاولة سرقة

### متى يحدث تلقائياً؟

- خلال **30 دقيقة**: ≥ **6** فشلاً موجّهاً لنفس البريد (بعد ربط المستخدم إن وُجد).
- النتيجة:
  - ضبط `users.security_locked_at`
  - إلغاء كل الجلسات النشطة وزيادة `session_version`
  - صف في `security_account_locks`
  - رفض تسجيل الدخول (`bhd=security_locked`)

### ماذا يفعل مالك الحساب؟

1. يفتح `/ar/security-unlock` (أو `/en/security-unlock`).
2. يعبّئ:
   - البريد المستخدم للحساب
   - الرقم المدني
   - تاريخ الميلاد
   - تاريخ انتهاء البطاقة
   - رقم واتساب
   - آخر معاملة (مرجع حجز أو مبلغ خلال سنة)
3. يستلم **رمز بريد** (6 أرقام، 15 دقيقة).
4. **واتساب:** القناة جاهزة في الكود وتُفعَّل بـ `WHATSAPP_OTP_ENABLED=1` عند ربط المزود؛ حالياً يكفي رمز البريد.
5. بعد التحقق يُفتح الحساب، ثم يستعيد كلمة المرور عبر `/forgot-password` (Identity).

بصمات الهوية تُحفظ مشفّرة/مقطّعة في `security_identity_fingerprints` للمقارنات اللاحقة.

---

## 5. إجراءات التشغيل عند اشتباه اختراق

1. افتح لوحة الأمن → **التهديدات** وحدّث الصفحة.
2. راجع **محاولات الدخول** حسب IP والدولة.
3. إن كان الهجوم من عنوان واحد: **حجر IP** فوراً.
4. إن استُهدف حساب معيّن: **قفل** من التبويب أو انتظر القفل التلقائي.
5. تواصل مع المالك عبر قناة موثوقة ووجّهه إلى `/security-unlock` — لا تطلب منه إرسال رموز OTP إليك.
6. بعد الفتح: اطلب منه تفعيل MFA (TOTP) من إعدادات الحساب عند التوفر، وراجع الجلسات النشطة.
7. سجّل الحادثة في التدقيق (الأحداث تُكتب تلقائياً عند الحجر/القفل/الفتح).

---

## 6. الخصوصية والاحتفاظ

- جلسات المنتج تخزّن **بصمة IP** ورمز الدولة فقط (لا عنوان خام على صف الجلسة).
- جداول الأمن (`security_auth_attempts`, `security_ip_quarantines`) تحتفظ بالعنوان الخام لعمليات مكافحة الاحتيال.
- لا تُعرض الأسرار أو رموز OTP في السجلات؛ الرموز تُقطَّع (hash) فقط.
- راجع أيضاً: `docs/phase-0/05-threat-model.md` و`docs/BHD-SESSION-POLICY.md`.

---

## 7. ترحيل القاعدة والتفعيل

- ملف الترحيل: `packages/db/migrations/custom/0052_platform_security_controls.sql`
- يُطبَّق تلقائياً مع `pnpm --filter @bhd-r/db migrate`
- متغيرات اختيارية:
  - `INTERNAL_SECURITY_SECRET` — لإشارات Identity
  - `WHATSAPP_OTP_ENABLED=1` — عند تفعيل واتساب
  - `PII_LOOKUP_PEPPER` — لمطابقة الرقم المدني مع أطراف المنشأة

## 8. ملخص سريع للمالك

| إشارة                    | رد النظام          | ردّك                                 |
| ------------------------ | ------------------ | ------------------------------------ |
| فشل متكرر من نفس IP      | حجر مؤقت           | راقب؛ أطلق إن كان خطأ شرعي           |
| فشل متكرر على حساب       | قفل + استعادة هوية | وجّه المالك لـ `/security-unlock`    |
| دول متعددة لنفس المستخدم | تنبيه في الفحص     | راجع الجلسات؛ اقفل عند الشك          |
| واتساب غير مفعّل         | OTP بريد فقط       | فعّل القناة لاحقاً دون تغيير الإجراء |
