# الحزمة التشغيلية المتكاملة — BHD R

هذه الوثيقة تصف الوحدات التي تعمل معاً داخل بوابات المالك والمطور والمستأجر. لا تعتمد
الواجهة على صفحة عامة تعيد استخدام جدول واحد؛ لكل وحدة بياناتها، صلاحياتها، حالات عملها
ونقاط API الخاصة بها.

## إدخال العقار

معالج الإدخال يتكون من ست مراحل:

1. نوع العقار وتصنيفه واللغتان والدولة والعملة والعنوان.
2. الوحدات، الطابق، الغرف، المساحة، الإيجار والتأمين وسعر البيع وغرض العرض.
3. بيانات التشغيل والمساحات والتأثيث ورسوم الإدارة والمرافق.
4. سند الملكية والقطعة والرقم البلدي والتأمين والعدادات والملاحظات.
5. الصور الآمنة؛ تمر بالفحص والمعالجة وتنتج نسخ WebP بعلامة BHD R المائية.
6. المراجعة والحفظ الذري بمفتاح idempotency.

يُنشئ النظام حصة ملكية أولية 100% للمالك المختار. إظهار الوحدة مربوط بثلاثة شروط:
تفعيل النشر، سلامة/جاهزية الوحدة، وعدم وجود حجز أو إيجار أو صيانة حاجبة للإتاحة.

## سير الحالات

- الطلبات والمصروفات والمهام: مسودة ← انتظار ← اعتماد ← تنفيذ ← اكتمال.
- المعاينة: طلب ← جدولة ← اكتمال ← تحويل، مع مسار عدم الحضور والإلغاء.
- البيع: عميل محتمل ← مؤهل ← معاينة/عرض ← تفاوض ← حجز ← تعاقد ← إغلاق ناجح.
- أمر العمل: مسودة ← عرض سعر ← انتظار اعتماد ← جدولة ← تنفيذ ← اكتمال ← تحقق.
- القضية: تقييم ← إنذار/إيداع ← جلسة ← حكم ← تنفيذ/تسوية ← إغلاق.
- القيد المحاسبي: مسودة ← مرحّل، ويمكن إنشاء قيد عكسي بدلاً من تعديل قيد مرحّل.

الـBackend يرفض القفزات غير المسموحة؛ زر الواجهة ليس هو طبقة الحماية.

## أهم نقاط API

- `/v1/portfolio/*`: العقارات والوحدات والعرض العام.
- `/v1/leasing/*`: الحجوزات والإيجارات والعقود.
- `/v1/finance/*`: الفواتير والمدفوعات والـwebhooks.
- `/v1/accounting/*`: الحسابات والقيود وميزان المراجعة والمصروفات.
- `/v1/operations/*`: الطلبات والمعاينات والبيع والموردون وأوامر العمل والقضايا والمهام والاعتمادات.
- `/v1/reports/*`: طلب التقرير وحالته والتنزيل المؤقت الموقّع.

كل مسار خاص مصنف مركزياً بصلاحية. اختبار `route-policy.test.ts` يفشل إذا أضيف handler
بلا تصنيف عام أو مصادق أو بصلاحيات واضحة.

## تشغيل التقارير

طلب التقرير يكتب `report_jobs` وحدث outbox داخل المعاملة نفسها. العامل الخلفي يستهلك
`report.requested`، يقرأ استعلاماً ثابتاً حسب نوع التقرير، وينشئ:

- CSV بترميز UTF-8 BOM وحماية الحقول.
- XLSX حقيقياً بصيغة Office Open XML، وليس CSV أعيدت تسميته.
- PDF مع تعطيل JavaScript والشبكة وتعقيم HTML.

يُحفظ الملف في الحاوية الخاصة، وتنتهي صلاحيته المنطقية بعد سبعة أيام. رابط التنزيل موقع
وقصير العمر ولا يكشف صلاحية عامة للملف.

## الفصل والأمان

- RLS مفعل ومفروض على الجداول الجديدة مع `organization_id`، والسجلات القانونية
  والمحاسبية والتشغيلية لا تظهر للمستأجر.
- يستطيع المستأجر إنشاء ورؤية طلباته فقط، ويرى عقوده وفواتيره وبلاغاته المرتبطة به.
- جميع المبالغ `bigint` بوحدات العملة الصغرى؛ لا توجد حسابات مالية بـfloat.
- القيود يجب أن تتوازن لكل عملة، وكل سطر إما مدين أو دائن.
- عمليات الإنشاء المالية والحساسة تدعم idempotency، والـwebhooks لها سجل فريد.
- الصور والمرفقات تمر بقيود النوع والحجم والفحص، والملفات الخاصة لا تقدم كرابط دائم.

## ما يلزم عند النشر

1. أخذ نسخة احتياطية ثم تشغيل الهجرات المولدة بالترتيب، ومنها `0001` و`0002`.
2. تطبيق ملف RLS بعد الهجرات ومنح دور العامل السياسات المبينة فيه.
3. تشغيل API والويب والعامل وRedis وPostgreSQL وS3-compatible storage معاً.
4. ضبط Chromium وClamAV والبريد ومفاتيح التشفير في بيئة العامل.
5. تنفيذ اختبار RLS المتكامل عبر `TEST_DATABASE_URL` و`TEST_MIGRATION_DATABASE_URL`.
6. عدم تدوير مفاتيح الإنتاج أو حذف بياناته إلا عبر Runbook وموافقة تشغيلية.

## حدود التسليم البرمجي

الكود يوفّر البنية والمسارات والاختبارات، لكنه لا يمنح صلاحيات إلى Vercel أو Render أو
Neon أو Redis أو S3 أو البريد ولا يدوّر أسرارها تلقائياً. كما أن اعتماد النصوص القانونية
والتوقيع المقبول قضائياً واختبار اختراق الإنتاج يحتاج قراراً وتفويضاً خارج المستودع.
