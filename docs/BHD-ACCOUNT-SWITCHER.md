المرجع البصري: قائمة حسابات جوجل (صورة دائرية ثم البريد في صف واحد). لا تعرض الاسم كمعرّف أساسي لأنه يتكرر بين الحسابات.

---

## 1. شكل البطاقة (إلزامي)

بعد النقر على صورة الحساب في الرأس تظهر بطاقة بيضاء عرضها ≈ 360px.

```
┌──────────────────────────────────┐
│  (صورة 56px)   email@domain     │  ← الحساب النشط
│       G         إدارة الحساب    │
├──────────────────────────────────┤
│  (صورة 40px)   other@domain      │  ← تبديل
│       G                          │
│  (+)           إضافة حساب آخر    │
├──────────────────────────────────┤
│  خروج من هذا الحساب              │
│  خروج من كل الحسابات             │
└──────────────────────────────────┘
```

| عنصر | القاعدة |
|---|---|
| الصف | `flex`، محاذاة وسط، فجوة 12px، ارتفاع صف القائمة 52px |
| الصورة | دائرة 40px (56px للحساب النشط). إن تعذّرت الصورة: الحرف الأول من الاسم أو البريد |
| النص الأساسي | **البريد** (`dir="ltr"` حتى في الواجهة العربية). وإلا اسم المستخدم ثم الهاتف |
| سطر ثانٍ | اسم المستخدم و/أو الهاتف فقط إن اختلفا عن البريد |
| شارة المصدر | دائرة 18px على زاوية الصورة: `G` جوجل · `f` فيسبوك · `WA` واتساب · `●` تسجيل عادي |
| إضافة حساب | دائرة بعلامة `+` ثم النص، نفس صف الصورة+النص |
| الخروج | صفوف نصية أسفل فاصل، بلا زر داكن عريض |

ممنوع: صف فيه الاسم فقط، أو «تبديل إلى: اسم»، أو أزرار خضراء/داكنة لكل حساب.

## 2. البيانات

من `GET https://id.bhd-om.com/api/auth/me` (مع بيانات الاعتماد إن كان الطلب من منتج):

```json
{
  "user": { "id": "…", "email": "a@x.com", "name": "…", "picture": "…", "username": null, "phone": null, "providers": ["google"] },
  "accounts": [ { "id": "…", "email": "b@x.com", "picture": "…", "providers": ["password"] } ]
}
```

- التبديل: `POST /api/auth/switch` `{ "sub": "<id>" }` ثم **حدّث الرأس من JSON فوراً**. ممنوع `reload` / `location.replace`.
- إضافة: `https://id.bhd-om.com/login?add=1`
- خروج هذا: `POST /api/auth/logout` — إن بقي حساب حدّث الرأس من JSON بلا وميض
- خروج الكل: `POST /api/auth/logout` `{ "all": true }` ثم `end-session?all=1`

## 5. سرعة بلا وميض (إلزامي في كل موقع)

المطلوب: تبديل الحساب وفتح موقع آخر في **جزء من الثانية**، بلا شاشة بيضاء وبلا سلسلة تحويلات في كل نقرة.

| الإجراء | القاعدة |
|---|---|
| تبديل حساب على الهوية | `POST /switch` → `setState` من الرد. لا تنقل الصفحة. صفحة `/account` تعيد جلب `/api/account` عبر حدث `bhd-account-changed` |
| تبديل حساب على منتج | نفس التحديث الفوري للرأس من JSON الهوية. لا `reload`. إن اختلف `sub` عن جلسة المنتج: تنقّل **مرة واحدة** إلى `{origin}{workspacePath}` (الميدلوير يحوّل إلى `start` فقط إن لزم) |
| فتح تطبيق آخر | `window.location.assign(origin + workspacePath)` أو `router.push` إن كان نفس المنشأ. **ليس** `/api/auth/bhd/start` في كل نقرة |
| أول زيارة بلا جلسة منتج | ميدلوير المنتج: لا جلسة → `302` إلى `start?returnTo=workspacePath` ثم SSO صامت |
| زيارة لاحقة وجلسة قائمة | الصفحة تُفتح مباشرة من `workspacePath` |
| التسخين | `preconnect` لمنشأ كل تطبيق عند أول مؤشر، و`prefetch` لمسار مساحة العمل عند فتح شبكة التطبيقات |

`startUrl` يبقى في الكتالوج للميدلوير والدخول الأول فقط. المشغّل والبوابة يستدعيان `launchUrlForApp` = مساحة العمل.

### ميدلوير المنتج (انسخ المنطق)

```
إن المسار محمي ولا توجد جلسة منتج صالحة
  → 302 إلى /api/auth/bhd/start?returnTo={المسار الحالي أو workspacePath}
وإلا
  → اعرض الصفحة فوراً
```

ممنوع: `start` عند كل فتح لتطبيق، `location.reload` بعد التبديل، انتظار Neon قبل رسم الرأس.

## 4. اختبار قبول

1. الحساب النشط: صورة دائرية كبيرة والبريد بجانبها، مقروء حتى لو تطابقت الأسماء.
2. حساب آخر: نفس الصف (صورة 40px + بريد). النقر يبدّل فوراً.
3. شارة المصدر ظاهرة على زاوية الصورة.
4. «إضافة حساب آخر» بنفس تخطيط الصورة+النص.
5. البطاقة لا تقطع البريد: قصّ بنقاط `ellipsis` لا لفّ عشوائي.
6. تبديل الحساب لا يبيّض الشاشة؛ البريد والصورة يتبدلان فوراً.
7. فتح تطبيق زُرته من قبل يفتح مساحة العمل في لمح البصر، بلا المرور بـ `start` إن كانت الجلسة قائمة.

انسخ هذا الملف كما هو إلى مستودع كل موقع BHD بعد نسخ `BhdAppSwitcher` و`lib/bhd/apps.ts`.
