# تقرير اكتمال النطاق الوظيفي V1 — BHD R

**تاريخ التحقق:** 24 أغسطس 2026

**النطاق:** النواة التشغيلية المعتمدة في خطة BHD R، وليست ميزات V1.5/V2/V3 المستقبلية.

## النتيجة

أصبحت BHD R منصة واحدة ذات مصدر حقيقة PostgreSQL واحد، وليست دمجاً بين النظام الحديث
والـLegacy. التطبيقات الثلاثة `web` و`api` و`worker` تستخدم العقود والسياسات والجداول نفسها.
النواة تغطي رحلة العقار من الإدخال والنشر إلى المعاينة والحجز والتحقق والتعاقد والتوقيع
والتفعيل والفوترة والتحصيل والتجديد والصيانة والإغلاق.

## الرحلة التشغيلية المكتملة

1. ينشئ المالك أو المطور عقاراً فردياً أو متعدد الوحدات عبر معالج من ست مراحل.
2. تحفظ بيانات العنوان، الإحداثيات، الملكية، السند، المرافق، العدادات، الوثائق والأسعار.
3. ترفع الصور إلى مساحة خاصة، وتفحص وتعالج، ثم تنتج نسخ AVIF/WebP عامة بعلامة BHD R.
4. لا يظهر الإعلان إلا إذا كان منشوراً والوحدة فعالة ومتاحة ولا يحجبها حجز أو إيجار أو صيانة.
5. يستطيع الزائر إرسال طلب معاينة آمن مع consent وhoneypot وidempotency.
6. تنشئ الإدارة Hold أو Reservation؛ ويولد الحجز قائمة متطلبات الهوية والعنوان.
7. يرفع المستأجر مستنداته الخاصة، ولا يعتمدها الموظف قبل اكتمال الفحص الأمني.
8. يمنع تحويل الحجز إلى إيجار إذا كان أي متطلب إلزامي مفقوداً أو غير معتمد.
9. ينشأ عقد مرقم ذرياً وLease مسودة وجدول فوترة، مع طلب اعتماد مركزي.
10. بعد الاعتماد يرسل العقد، ويولد العامل PDF ثابتاً وHash ويرسل طلب التوقيع.
11. يوقع المالك والمستأجر بعد challenge حديث أو TOTP، وتحفظ أدلة التوقيع دون IP خام.
12. لا يتفعل Lease وجدول الفوترة إلا بعد اكتمال توقيع الطرفين.
13. يحصل المستأجر على اسم مستخدم ورابط تفعيل أحادي الاستخدام؛ لا ترسل كلمة مرور دائمة.
14. يصدر العامل فواتير الاستحقاقات، وتدعم المدفوعات الجزئية والإيصالات والاسترداد والتسوية.
15. التجديد ينشئ ملحقاً مستقلاً يمر بالاعتماد وPDF وتوقيع الطرفين؛ لا يتغير Lease قبله.
16. بلاغات الصيانة وأوامر العمل والموردون والمهام والطلبات والقضايا والموافقات مترابطة.
17. التقارير تنشأ في Worker كـCSV/XLSX/PDF خاص، وتقدم برابط موقع قصير العمر.

## ضوابط الأمان المنفذة

- Policy Guard مركزي fail-closed واختبار يصنف كل handler.
- عزل المؤسسة في الخدمة وRLS مفروض في PostgreSQL، مع اختبار شركة A/B ومستأجرين مختلفين.
- redaction متداخل للسجلات والتدقيق، وفحص مصدر يمنع أنماط الأسرار المعروفة.
- CSRF بالـOrigin وdouble-submit، وCSP ورؤوس أمان وقيود للمرفقات.
- Password reset وactivation tokens مهشمة قصيرة العمر وإلغاء الجلسات القديمة.
- TOTP يمنع replay، وAPI Keys مهشمة ومحددة النطاق والمدة وتظهر مرة واحدة.
- تشفير versioned مع AAD للسياق، وقراءة مفاتيح قديمة وكتابة بالإصدار النشط للتدوير.
- منع SSRF لبوابات الدفع عبر allowlist وDNS/IP وredirect policy.
- webhook signatures وevent uniqueness وidempotency لمنع تكرار الدفعات.
- تعقيم HTML وقوالب العقود وتعطيل شبكة/JavaScript في PDF لمنع XSS وSSRF.
- روابط الفاتورة والملفات العامة تعرض DTO محدوداً، ومؤقتة أو موقعة عند الخصوصية.

## أدلة التحقق الآلية

- `pnpm verify:source`: نجح فحص تسرب الأسرار في المصدر.
- `pnpm lint`: نجح على 13 حزمة.
- `pnpm typecheck`: نجح على 13 حزمة.
- `pnpm test`: نجحت اختبارات API وWeb وWorker والحزم.
- `pnpm build`: نجح بناء NestJS وWorker وNext.js وإنتاج 48 صفحة.
- `pnpm test:e2e`: نجحت 3 اختبارات API E2E و22 رحلة Playwright على Chromium والجوال.
- PostgreSQL 17/PostGIS مؤقت: نجحت الهجرات `0000` حتى `0007` ونجحت 6 اختبارات DB،
  ومنها اختبار RLS المتكامل غير المتجاوز بصلاحية superuser، واختبار 100 Webhook متزامن
  الذي أثبت إنشاء حدث واحد وسجل دفع واحد.
- `pnpm audit --prod --audit-level high`: لا توجد ثغرات معروفة وقت التحقق.
- `pnpm format:check`: جميع الملفات مطابقة لـPrettier.

## الهجرات الجديدة المهمة

- `0003`: الأطراف، الفوترة الدورية، جلسات الدفع، الإيصالات، الاسترداد وتسلسلات العقود.
- `0004` و`0005`: تسلسلات القيود وقيود المصروفات المالية.
- `0006`: متطلبات ومستندات الحجز ومراجعتها.
- `0007`: أنواع العقود وروابط ملحقات التجديد بالعقد الأصلي.

ملف RLS المخصص يعاد تطبيقه بصورة idempotent بعد الهجرات، ولا يكفي تشغيل SQL المولد وحده.

## حدود لا يحلها المستودع وحده

- لا تعد هذه الوثيقة اعتماداً قانونياً لصيغة العقد أو التوقيع في سلطنة عمان.
- لا تثبت إعدادات Vercel/Neon/Redis/S3/Sentry والبريد وBHD Identity الفعلية دون وصول إليها.
- لا يمكن تدوير مفاتيح الإنتاج أو اختبار الاستعادة من نسخته الحقيقية من داخل المستودع.
- ميزات المزادات والملكية الجزئية والتمويل والذكاء الاصطناعي وVR هي V2/V3 بحسب الخطة،
  وليست جزءاً من بوابة قبول V1.

## أمر التسليم

قبل النشر خذ نسخة احتياطية، ثم نفذ migration job بحساب المهاجر، وطبّق أدوار التشغيل،
وشغّل API وWorker وWeb، ثم نفذ smoke على بيئة canary. لا تشغل الهجرات أثناء `next build`.
