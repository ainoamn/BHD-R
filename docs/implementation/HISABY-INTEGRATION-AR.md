**تاريخ:** 2026-09-09

**المستودعات:**
- عقارات: [ainoamn/BHD-R](https://github.com/ainoamn/BHD-R) · إنتاج https://r.bhd-om.com

## 1) ماذا تريد اليوم (تفسير المتطلب)

على [`/ar/owner/accounting`](https://r.bhd-om.com/ar/owner/accounting) وما يرتبط بها:

| حاجة المالك | أين تُلبّى |
| --- | --- |
| تتبع المدفوعات: المصدر، أين حُفظت، وارد/صادر | **BHD-R مبسّط** + مرآة في **Hisaby** |
| فواتير عادية + طباعة/كشوفات تشغيلية | **BHD-R** (فواتير إيجار/إقامة + PDF الموجود) |
| محاسبة مفصّلة: دليل حسابات، قيود مزدوجة، VAT، تقادم، تقارير GL | **Hisaby فقط** |
| ظهور نفس الحركات في Hisaby مباشرة | **ربط API / أحداث** (لم يُبنَ بعد) |

---

## 2) قرار مهم: لا ننسخ Hisaby أو bhd-om داخل BHD-R

### لماذا لا «نسخ برنامج الحسابات كاملاً» إلى BHD-R؟

1. **[hisaby](https://github.com/ainoamn/hisaby)** هو بالفعل برنامج المحاسبة الكامل (Nest + Next + Prisma: فواتير، GL، VAT، طباعة PDF، بنوك، رواتب، POS…). نسخه داخل BHD-R يكرّر منتجين وقاعدة بياناتين لنفس الغرض ويصعّب الصيانة.
2. **[bhd-om](https://github.com/ainoamn/bhd-om)** الحالي ليس حزمة محاسبة SaaS جاهزة للنسخ؛ README الظاهر يركّز على أرشفة/تشفير. قواعد العمل العقارية منه تُستخرج عبر adapters عند الحاجة — لا dump للكود.
3. طلبك نفسه يقول: في العقارات **حسابات مبسّطة**، والمفصّل في Hisaby — هذا **تكامل** لا **دمج مستودعات**.

### القرار المعماري (D-207 مفعّل كتوجيه)

```
BHD-R (عقارات)                    Hisaby (محاسبة)
─────────────────                 ─────────────────
فواتير إيجار/إقامة مبسّطة   ──►  فاتورة مبيعات / قيد GL
مدفوعات + مصدر + عقار/وحدة  ──►  سند قبض + ترحيل حسابات
مصروفات عقار مبسّطة         ──►  فاتورة مشتريات / مصروف
عرض تشغيلي + رابط «افتح في Hisaby»
                                  تقارير، ميزان، VAT، كشف حساب
```

- **مصدر الحقيقة التشغيلي للعقار:** BHD-R (عقود، حجوزات، وحدات).  
- **مصدر الحقيقة المحاسبي المفصّل:** Hisaby.  
- **SSO موجود:** `bhd-hisaby` في `apps/web/src/lib/bhd/apps.ts` → https://hisaby.bhd-om.com

## 3) الوضع الحالي في BHD-R (صريح)

صفحة المحاسبة اليوم **ليست** مركز محاسبة كامل:

| موجود | ناقص مقابل طلبك |
| --- | --- |
| قائمة قيود/مدفوعات إقامة (Neon-first) | مصدر الدفع وحساب وارد/صادر واضحان في UI |
| أقسام فواتير / مدفوعات / مصروفات منفصلة | دمج تشغيلي واحد «تتبع مالي» |
| PDF فاتورة إيجار عبر worker عند الإصدار | طباعة كشف حساب / بيان من شاشة المحاسبة |
| Nest `/v1/accounting/*` و`/v1/finance/*` داخلي | **لا مزامنة** مع Hisaby API |
| رابط منتج Hisaby عبر SSO | لا دفع أحداث ولا webhook ثنائي |

جرد تقني: انظر `docs/implementation/STATUS.md` وإصدارات 0.4.76–0.4.77.

## 4.0 من ينشئ مفتاح API؟

التفاصيل التشغيلية وأمر وكيل Hisaby: [`HISABY-API-KEYS-AR.md`](./HISABY-API-KEYS-AR.md)

| الغرض | المنشئ | الصفحة |
| --- | --- | --- |
| رمز يستقبله Hisaby من BHD-R (دفع أحداث) | **Hisaby** | إعدادات تكامل Hisaby |
| مفتاح يقرأ به Hisaby بيانات BHD-R | **مالك العقارات في BHD-R** | `/ar/owner/api-keys` |
| جلسة المستخدم | SSO | هوية BHD |

---

### 4.1 هوية وربط مؤسسة

| حقل | معنى |
| --- | --- |
| `bhdR.organizationId` | مؤسسة BHD-R |
| `hisaby.companyId` | شركة Hisaby |
| ربط عبر SSO BHD Identity + جدول `hisaby_links` في BHD-R |

### 4.2 أحداث تُدفع من BHD-R (outbox)

| حدث BHD-R | هدف Hisaby (مفهومي) |
| --- | --- |
| `stay.payment.succeeded` | سند قبض + قيد إيراد إقامة (مركز تكلفة = عقار) |
| `lease.invoice.issued` | فاتورة مبيعات |
| `lease.payment.received` | تحصيل على الفاتورة |
| `expense.approved/paid` | مصروف / فاتورة مشتريات |
| `deposit.held/released` | قيود أمانات |

كل حدث يحمل: `idempotencyKey`, `source` (`bhd-r`), `organizationId`, `propertyId`, `unitId?`, `amountMinor`, `currency`, `occurredOn`, `counterparty`, `memo`, روابط مستندات.

### 4.3 قراءة عكسية (Hisaby → BHD-R) — مزامنة تلقائية

بعد لصق مفتاح قراءة BHD-R في Hisaby (`/bhd-r`):

- Hisaby يسحب العقارات (مع العناوين)، الوحدات، الأطراف، الإيجارات، الفواتير، المدفوعات الواردة، المصروفات الصادرة، والموردين من `https://api.r.bhd-om.com`.
- المزامنة تبدأ فوراً بعد الحفظ ثم كل **15 دقيقة** بدون تدخل بشري (`POST /api/integrations/bhd-r/sync` يدوي اختياري).
- قائمة العقارات `GET /v1/portfolio/properties` تتضمن `address` حتى تُحفظ العناوين في المحاسبة.
- صلاحيات المفتاح: زر «تعبئة صلاحيات حسابي الكاملة» في `/ar/owner/api-keys`.


### 4.4 أمان

- مفتاح خدمة أو OAuth app-to-app بين المستودعين.  
- لا نسخ أسرار Hisaby داخل Git.  
- Idempotent webhooks في الاتجاهين.

> تفاصيل مسارات Hisaby الفعلية تُثبت من Swagger الحي `https://hisaby.bhd-om.com` / ` /api/docs` عند بدء التنفيذ في مستودع hisaby أيضاً.

## 5) ماذا يبقى «مبسّطاً» داخل BHD-R (تحسين `/owner/accounting`)

مرحلة منتج داخل BHD-R فقط (بدون انتظار Hisaby الكامل):

1. **بطاقة حركة مالية موحّدة:** المرجع، التاريخ، البيان، المبلغ، الاتجاه (وارد/صادر)، المصدر (`stay` / `lease` / `manual` / `expense`)، العقار/الوحدة، حالة الحفظ (Neon/Nest)، حالة المزامنة مع Hisaby.  
2. **فلاتر:** عقار، فترة، مصدر، حالة مزامنة.  
3. **إجراءات:** فتح الفاتورة/الحجز، تنزيل PDF إن وُجد، «فتح في Hisaby» عند الربط.  
4. **كشوفات تشغيلية خفيفة:** CSV/طباعة قائمة الحركات للفترة (ليست ميزان مراجعة — ذلك في Hisaby).  
5. الإبقاء على `/invoices` و`/payments` و`/expenses` كشاشات تفصيل؛ المحاسبة = لوحة تتبع.

لا نعيد بناء شجرة حسابات Hisaby داخل BHD-R.

---

## 6) ماذا يُستفاد من bhd-om (بدون نسخ أعمى)

- استخراج **قواعد أعمال** قديمة (إن وُجدت مسارات sync محاسبة في `legacy` أو docs) كمتطلبات اختبار.  
- **لا** نسخ Prisma/UI الخاصة بـ bhd-om إلى monorepo BHD-R.  
- أي شاشة تراث مفيدة تُعاد كتابتها على عقود BHD-R + Hisaby.

## 7) خطة التنفيذ المرحلية

| مرحلة | نطاق | مستودع | نتيجة قابلة للتجربة |
| --- | --- | --- | --- |
| **A** | تحسين محاسبة BHD-R المبسّطة (مصدر، عقار، وارد/صادر، CSV/طباعة قائمة، روابط PDF) | BHD-R | المالك يتتبع المدفوعات بوضوح على `/owner/accounting` |
| **B** | جدول ربط مؤسسة + إعدادات Hisaby + زر SSO «المحاسبة المفصّلة» | BHD-R | انتقال مباشر لـ Hisaby بنفس جلسة BHD |
| **C** | Outbox أحداث مالية + endpoint استقبال في Hisaby (أو العكس باتفاق الفريق) | BHD-R + hisaby | دفع إقامة ناجح يظهر كسند/قيد في Hisaby |
| **D** | عرض حالة المزامنة ورقم القيد في BHD-R | BHD-R | شفافية كاملة للمالك |
| **E** | كشوفات/تقارير ثقيلة تبقى في Hisaby؛ روابط عميقة فقط | hisaby | لا ازدواج تقارير |

**تقدير:** A أيام قليلة؛ C–D أسبوعان+ عبر مستودعين؛ نسخ Hisaby كاملاً داخل BHD-R = أشهر وصيانة مزدوجة — **مرفوض**.

---

## 8) معايير قبول (بعد التنفيذ)

1. من `/ar/owner/accounting` أرى لكل حركة: المصدر، العقار، وارد/صادر، أين حُفظت، ورابط فاتورة/PDF إن وُجد.  
2. بعد دفع إقامة ناجح ومع ربط Hisaby: تظهر الحركة في Hisaby دون إدخال يدوي.  
3. المالك يستخدم Hisaby لدليل الحسابات وميزان المراجعة والـ VAT — وليس نسخة مكررة داخل BHD-R.  
4. لا يُدمج كود frontend/backend الخاص بـ hisaby كشجرة فرعية داخل BHD-R.

---

## 9) الخطوة التالية المطلوبة منك

اختر للبدء الفوري:

- **A** — تحسين شاشة المحاسبة المبسّطة في BHD-R الآن.  
- **B+C** — بدء عقد التكامل مع مستودع hisaby (يحتاج صلاحية كتابة على hisaby أيضاً).  
- الاثنان بالتوازي على جهازين/وكيلين.

بعد الاختيار ننفّذ ونرفع على `main` كالعادة.
