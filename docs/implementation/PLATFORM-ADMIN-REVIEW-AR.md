# تقرير مراجعة المنصة وبناء لوحة الإدارة — 0.8.134.85

تاريخ: 2026-10-21  
النطاق: مراجعة من أ إلى ي، تشخيص الفجوات، وبناء لوحة `/platform` الموحدة.

---

## 1) ملخص تنفيذي

المنصة كانت مقسومة بين سطحين:

| السطح | المسار | الحالة قبل هذا الإصدار |
|--------|---------|-------------------------|
| إدارة الموقع التشغيلية | `/site-admin` | مكتملة نسبياً (شكاوى، توثيق، باقات، مستخدمون، تفويض) |
| بوابة المنصة | `/platform` | جداول عامة ضعيفة عبر Nest بدون تشخيص أو أمن أو إحصائيات اشتراك |

**ما شُحن الآن:** لوحة مشرف موحّدة تحت `/platform` مع:

1. نظرة عامة  
2. **تشخيص النظام**  
3. **الاشتراكات والباقات**  
4. **إحصائيات الاشتراك / تقدير التحصيل**  
5. **المستخدمون**  
6. المنشآت  
7. **الأمن والتدقيق** (بصمات IP مجزّأة + الجلسات + سجل التدقيق)  
8. رابط لتشغيل الموقع (`/site-admin`)

الدخول عبر `/admin` أو `/api/auth/admin-entry` يوجّه إلى `/platform`.

---

## 2) أخطاء ومشاكل مكتشفة (قبل/أثناء المراجعة)

### 2.1 هيكلية وتجربة

- ازدواج إدارة: `/site-admin` غني و`/platform` هزيل — المشرف لا يجد «صفحة أدمن» واحدة.
- صفحات المنصة (منشآت/مستخدمون/تدقيق) كانت جداول generic بلا أدوات فعل.
- لا توجد صفحة تشخيص صحة النظام في الواجهة.
- لا توجد شاشة أمن/اختراقات؛ فقط `audit_logs` خام عبر Nest.
- تحصيل اشتراكات SaaS **يدوي** (حالة + ملاحظة) — لا فواتير اشتراك آلية ولا بوابة دفع للباقات.

### 2.2 عزل وحماية

| الطبقة | الموجود | الفجوة |
|--------|---------|--------|
| صلاحيات المنصة | `platform_admin` / `platform_support` في authz | دعم المنصة لا يرى الباقات/المستخدمين إلا بتفويض site-admin |
| عزل المستأجر (RLS) | `app.platform_admin` / org scope في Neon | عمليات elevated صحيحة للإدارة |
| التدقيق | `audit_logs` + interceptor Nest + أحداث site_admin | لا لوحة تصفية/تنبيه |
| IP | `ipHash` فقط (جيد للخصوصية) | لا قائمة حظر، لا فشل دخول مُجمَّع، لا geo |
| المعدل | rate-limit في الذاكرة لكل مسار | لا يُعرض في الأدمن ولا يُpersist |
| الأرشفة | حالات عقود/عقارات/مهام | لا سياسة أرشفة SaaS موحّدة للمنشآت الملغاة |
| التشفير | مفاتيح الحقول الحساسة | backfill API موجود بدون زر في الواجهة بعد |

### 2.3 منتج (عقارات / إقامة / محاسبة)

- مسار استرداد التأمين اكتمل مؤخراً (حالات للمستأجر، مستندات التحويل/عكس المعاملة، مهمة عدم الاستلام).
- لا يزال تحصيل اشتراك المنصة منفصلاً عن محاسبة المنشأة (صحيح معمارياً، لكن يحتاج «مكتب اشتراكات» أوضح — وُفّر تقدير MRR).

## 3) آلية التطوير والتحديث المقترحة

### 3.1 دورة الإصدار

1. فرع قصير أو عمل مباشر على `main` حسب السياسة الحالية (نشر فوري للتجربة على `r.bhd-om.com`).  
2. `CHANGELOG.md` لكل تغيير موجّه للمستخدم.  
3. `git push` → نشر Vercel/التدفق الحالي.  
4. تحقق على الحي (المالك لا يعتمد محلياً).

### 3.2 طبقات الكود

```
apps/web     → واجهات Portals + Neon APIs للإدارة الثقيلة
apps/api     → Nest: نظرة عامة، قوائم، تدقيق، إعدادات صحة البيئة
packages/*   → authz, db, domain, i18n
```

**قاعدة:** كتابات site-admin تبقى على Neon (`/api/site-admin/*` و`/api/platform/*` الجديدة). Nest للقراءة العرضية والصحة.

### 3.3 كيف نبني صفحة Admin (ما طُبّق)

```
/{locale}/platform                 نظرة عامة
/{locale}/platform/diagnostics     تشخيص
/{locale}/platform/subscriptions   باقات + اشتراكات (PlansAdmin)
/{locale}/platform/billing         إحصائيات تقديرية
/{locale}/platform/users           UsersAdmin
/{locale}/platform/organizations   قائمة المنشآت
/{locale}/platform/security        تدقيق + جلسات
/{locale}/site-admin/*             تشغيل: شكاوى / توثيق / تفويض
```

الحراسة:

- بوابة المنصة: دور `platform_*` عبر `PortalShell`.  
- باقات/مستخدمون/فوترة: نطاق site-admin (`plans` / `users`) عبر `requireSiteAdminPage`.

## 4) تحسينات مقترحة لكل نطاق صفحات

### 4.1 إدارة المنصة (`/platform`) — مرحلة تالية

- زر backfill التشفير من صفحة التشخيص.  
- فواتير اشتراك حقيقية + بوابة دفع SaaS.  
- قائمة حظر IP / تنبيهات فشل دخول مُخزَّنة.  
- انتحال دعم آمن (impersonation) بزمن محدود وتدقيق إجباري.  
- أرشفة منشأة ملغاة (قراءة فقط + تصدير).

### 4.2 المالك / المطوّر

- توحيد تنبيهات «تحتاج إجراء» عبر الحجوزات والمحاسبة والطلبات.  
- لوحة أداء عقار (إشغال، تحصيل، شكاوى تأمين).  
- تقليل النوافذ المنبثقة الكثيفة على الجوال.

### 4.3 المستأجر / الضيف

- مركز مهام موحّد (استرداد تأمين، طلبات، معاينات).  
- وضوح حالات الدفع والاسترداد (بدأ جزئياً في `/tenant/payments`).

### 4.4 المحاسبة

- ربط مستندات GL (`deposit_refund`) بروابط من تبويب الأمانات.  
- تقارير ثقة التأمين (held / transferred / retained) شهرية.

### 4.5 الإقامات اليومية

- مراقبة معدل الإلغاء وعدم الحضور في الأدمن.  
- تنبيهات SLA لاسترداد التأمين (أيام الانتظار).

## 5) طبقات عزل / حماية / أرشفة — هل نحتاج تطبيقها؟

| الطبقة | الأولوية | توصية |
|--------|----------|--------|
| حظر IP + سجل فشل الدخول | عالية | جدول `platform_security_events` + واجهة في `/platform/security` |
| أرشفة اشتراك ملغى | متوسطة | حالة `archived` تمنع الكتابة وتبقي القراءة للتقارير |
| فصل بيانات SaaS عن بيانات المستأجر محاسبياً | موجودة جزئياً | الإبقاء + دفتر اشتراكات مستقل |
| نسخ احتياطي / PITR Neon | عالية تشغيلياً | خارج الكود — سياسة تشغيل |
| Retention للـ audit (مثلاً 18 شهراً) | متوسطة | job أرشفة إلى تخزين بارد |
| MFA إجباري لـ `platform_admin` | عالية | عبر BHD Identity |

## 7) خطة قصيرة بعد النشر

1. فتح `https://r.bhd-om.com/ar/platform` بحساب `platform_admin`.  
2. التحقق من التشخيص (هوية، SMTP، outbox).  
3. مراجعة الاشتراكات والإحصائيات.  
4. فتح الأمن والتدقيق والتأكد من ظهور أحداث `site_admin.*`.  
5. جدولة مرحلة 2: دفع الاشتراكات + حظر IP + MFA إجباري.

## 8) خلاصة

لوحة الأدمن أصبحت موجودة فعلياً تحت `/platform`، مع تشخيص وإدارة اشتراكات/مستخدمين وإحصائيات تقديرية ومتابعة تدقيق/جلسات. الفجوات الأهم المتبقية تشغيلية: **تحصيل اشتراك آلي**، **مراقبة اختراقات قابلة للتنفيذ (حظر)**، و**أرشفة منشآت ملغاة** — مذكورة أعلاه كمسار تطوير واضح.
