# تنقل سلس — كيف يعمل الموقع

**تاريخ:** 2026-09-11  
**إصدار مرتبط:** 0.4.81+ (مهلات Neon) · تأكيد تجربة soft-nav

## الهدف (ما طلبته)

عند فتح الموقع مباشرة:

1. تُرسم **الصفحة الحالية فوراً**.  
2. في **الخلفية** يُحمَّل/يُجهَّز باقي المسارات المهمة.  
3. التنقل بين الصفحات يبدو **غير محسوس** — كأن المستخدم يبقى في نفس الصفحة (بدون إحساس إعادة تحميل كاملة).

## منطقتان

### أ) الموقع العام (الرئيسية، العقارات، الثقة…)

| آلية | دور |
| --- | --- |
| `MarketingRoutePrefetch` | بعد الرسم: prefetch للصفحات الخفيفة ثم `/properties` و`/portal` ثم عيّنة من صفحات الوحدات/العقارات |
| روابط `prefetch` على البطاقات | تجهيز صفحة التفاصيل عند ظهورها في القائمة |
| مهلات Neon (≤8 ث) | لا يُسمح لتعليق الخلفية أن يجمّد النقر دقيقتين |

### ب) بوابة المالك/المطوّر (`/owner` …)

| آلية | دور |
| --- | --- |
| `PortalRoutePrefetch` | طابور متدرّج لكل أقسام الشريط + روابط التفاصيل المكتشفة |
| `warmOpsSection` / ذاكرة ops | بيانات الأقسام تُسخَّن وتُعرض من الذاكرة عند التبديل |
| `PortalMainSlot` | لوحات التشغيل تبقى مركّبة؛ التبديل يغيّر الظهور فقط |
| History API للـ ops | بدون إعادة تحميل المستند |

## ما لا يُحمَّل بالكامل مقدماً

- كل وحدات الكتالوج في العالم (آلاف الصفحات) — تُجهَّز العيّنة الظاهرة + ما يُكتشف أثناء التصفح.  
- حسابي / بوابة BHD الخارجية — نطاقات أخرى خارج soft-nav هذا الموقع.  
- إن فشل Neon/Nest: الصفحة تظهر باحتياطي سريع بدل الانتظار اللانهائي.

## خلاصة للمالك

نعم: التصميم هو **رسم فوري + تسخين خلفي + تنقل داخل نفس الغلاف**.  
إصلاح 0.4.81 ضمن أن التسخين الخلفي **لا يعلّق** الموقع؛ التأكيد هنا يعيد prefetch أسرع للمسارات الثقيلة مع الإبقاء على المهلات.
