## أ) مسار الإيجار (من تخزين العقار حتى الشغور ثم الإيجار من جديد)

```mermaid
flowchart TD
  A[سجل العناوين<br/>مالك / مستأجر / مستخدم] --> B[تسجيل عقار + وحدات<br/>ربط المالك من السجل]
  B --> C{وحدة شاغرة؟}
  C -->|نعم| D[حجز: وحدة شاغرة + مستأجر من السجل<br/>status=pending]
  D --> E[المحاسب يؤكد العربون<br/>status=confirmed]
  E --> F[قيد محاسبي تلقائي<br/>Dr 1000 / Cr 2100]
  F --> G[إنشاء عقد إيجار قيد الإجراء<br/>leases.draft]
  G --> H[مبالغ: إيجار / ضمان / سماح / أخرى / شيكات]
  H --> I[سلسلة اعتماد<br/>محاسب → مالي → إدارة]
  I --> J[إرسال للتوقيع الإلكتروني]
  J --> K[توقيع الأطراف]
  K --> L[تفعيل → leases.active]
  L --> M[ظهور في بوابات المالك/المستأجر/الحسابات<br/>خروج من قوائم الشاغر]
  M --> N{قرار لاحق}
  N -->|تجديد| O[ملحق تجديد موقّع]
  O --> G
  N -->|إنهاء طبيعي| P[leases.ended]
  N -->|فسخ| Q[leases.terminated]
  P --> R[تلقائي: مهمة شغور]
  Q --> R
  R --> S[صيانة تسليم vacancy_handover]
  S --> T[محاماة مراجعة تأمين]
  T --> U[مصروف مخالصة vacancy_settlement]
  U --> C
```

### حالات الإيجار المختصرة

| المرحلة | الكود في النظام | المسؤول |
|---------|------------------|---------|
| حجز معلّق | `reservations.pending` | عمليات |
| عربون مؤكد | `reservations.confirmed` + قيد `reservation_deposit` | محاسب |
| قيد الإجراء | `leases.draft` + اعتمادات + شيكات | محاسب/مالي/إدارة |
| ساري | `leases.active` بعد توقيع | عمليات |
| تجديد | ملحق → يعود لدورة مسودة/ساري | عمليات |
| منتهٍ / مفسوخ | `ended` / `terminated` | عمليات |
| شاغر مرة أخرى | مهمة + صيانة + محاماة + مصروف | تلقائي ثم متابعة |

## ب) مسار البيع (منفصل عن الإيجار)

```mermaid
flowchart TD
  A[سجل العناوين] --> B[عقار/وحدة لغرض البيع]
  B --> C[sales_deals: lead]
  C --> D[qualified]
  D --> E[viewing]
  E --> F[offer]
  F --> G[negotiation]
  G --> H[reserved]
  H --> I[contracting]
  I --> J[closed_won]
  C -.-> X[closed_lost / cancelled]
  D -.-> X
  E -.-> X
  F -.-> X
  G -.-> X
  H -.-> X
  I -.-> X
  X -.->|من closed_lost فقط| C
```

### حالات البيع المختصرة

| المرحلة | الكود | ملاحظة |
|---------|-------|--------|
| عميل محتمل | `lead` | بداية الصفقة |
| مؤهل | `qualified` | |
| معاينة | `viewing` | قد ترتبط بطلب معاينة تشغيلي |
| عرض / تفاوض | `offer` → `negotiation` | |
| محجوز بيع | `reserved` | ليس نفس حجز الإيجار |
| تعاقد | `contracting` | |
| ناجح | `closed_won` | نهاية سعيدة |
| خسارة | `closed_lost` | يمكن الرجوع لـ `lead` |
| ملغى | `cancelled` | نهاية |

## ج) حلقة حياة الوحدة

```mermaid
stateDiagram-v2
  [*] --> شاغر
  شاغر --> مؤجر: حجز→عربون→عقد→تفعيل
  مؤجر --> شاغر: إنهاء أو فسخ + متابعة شغور
  شاغر --> مباع: مسار بيع closed_won
  مؤجر --> مؤجر: تجديد
```

## د) نقاط أعتقد أنها تحتاج مراجعتك

1. **بيع بعد `closed_won`:** هل تريد نقل ملكية تلقائي في النظام أم إجراء يدوي خارجي؟
2. **التجديد:** هل يكفي ملحق موقّع ثم تفعيل، أم جدول شيكات/فوترة جديد إلزامي كل مرة؟
3. **الفسخ مقابل الإنهاء:** هل مخالصة التأمين تختلف بينهما؟
4. **البيع من وحدة كانت مؤجرة:** هل يُمنع البيع إلا بعد إنهاء الإيجار؟
5. **Nest على الإنتاج:** بدون `API_INTERNAL_ORIGIN` المسار التشغيلي لا يكتمل على Vercel.
