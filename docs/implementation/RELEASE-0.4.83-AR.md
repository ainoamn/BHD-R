# إصدار 0.4.83 — صور المعرض بدون تأخير ~20 ثانية

**تاريخ:** 2026-09-11  
**مثال:** https://r.bhd-om.com/ar/units/94dac017-b46e-4a0e-9474-1b7a17fbdc68

## السبب

النص يظهر أولاً لأن صفحة الوحدة ترسم من Neon بسرعة نسبية، بينما كل صورة كانت تمر عبر:

`/api/public/media/:id` → Neon → GetObject من R2 الخاص → تخزين كامل في ذاكرة Vercel (`iad1`) → إرسال البايتات للمستخدم في عُمان.

مع 8 صور جاهزة دفعة واحدة، و`Cache-Control` قصير (5 دقائق)، كان الشعور ~10–20 ثانية حتى يكتمل المعرض.

## الإصلاح

1. **307 إلى رابط موقّع قصير العمر** نحو R2/S3 — المتصفح يحمّل البايتات من التخزين مباشرة، ليس عبر Vercel.  
2. عميل S3 موحّد + كاش روابط موقّعة داخل الـ isolate.  
3. كاش أطول للصور المضمنة (inline).  
4. `preload` للصورة الرئيسية + `fetchPriority` / `loading=lazy` للمصغّرات.  
5. عدم منافسة prefetch الكتالوج على صفحات التفاصيل.

العلامة المائية تبقى CSS (`.media-watermark`) فوق الصورة.
