# سياسة بيانات البطاقة والدفع — BHD R Stays

**تاريخ:** 2026-09-03  
**الإصدار المرتبط:** 0.4.52

## القاعدة الذهبية

**لا يُسمح أبداً بحفظ رقم البطاقة الكامل (PAN) أو رمز الأمان (CVC/CVV) أو تاريخ الانتهاء في قاعدة بيانات BHD R** — حتى في صفحة الأدمن، وحتى «للأمان». هذا مخالف لمعيار PCI DSS ويعرّض المنظومة للمساءلة القانونية.

## ماذا يُحفظ عندنا (آمن)

| الحقل | أين | من يراه |
| --- | --- | --- |
| آخر 4 أرقام | سجل تأكيد الدفع / العقد | المالك + الإدارة |
| اسم حامل البطاقة المدخل | نفس السجل | المالك + الإدارة |
| نوع البطاقة (Visa / Mastercard…) | نفس السجل | المالك + الإدارة |
| مرجع جلسة الدفع (`providerIntentId`) | `stay_payment_intents` | الإدارة / الأنظمة |

رقم البطاقة الكامل وCVC يبقيان في متصفح الضيف فقط أثناء التجربة (sandbox) ولا يُرسلان إلى الخادم.

## كيف تعمل الاسترجاعات (Refunds) في الأنظمة الحقيقية؟

1. بوابة الدفع (Thawani / Stripe / شبكة بنكية…) تستلم البطاقة عبر صفحة آمنة أو SDK.
2. تُرجع **رمزاً (token / payment_intent_id)** وليس رقم البطاقة.
3. عند الإلغاء أو الاسترجاع نستدعي API البوابة بـ:  
   `refund(payment_intent_id)`  
   فتعيد البوابة المبلغ إلى **نفس البطاقة** بدون أن نعرف رقمها.

لذلك الاحتفاظ برقم البطاقة **ليس مطلوباً** للاسترجاع — المطلوب هو مرجع الدفع عند المزود.

## وضعنا الحالي (تجريبي)

- الدفع sandbox محلي؛ لا يوجد مزود حي بعد.
- الاسترجاع الآلي للبطاقة الحقيقية غير متاح حتى ربط PSP.
- عند ربط بوابة حيّة: نفس الحقول الآمنة (آخر 4 + اسم + brand + token) فقط.

## ماذا لو أردنا «أدمن فقط»؟

يمكن لاحقاً إخفاء آخر 4 أرقام واسم الحامل عن المالك/الضيف وإظهارها فقط في `/platform` — لكن **لا يمكن** تخزين الرقم الكامل هناك أيضاً. الإدارة ترى نفس الحقول الآمنة + سجلات التدقيق.
