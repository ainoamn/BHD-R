# الإصدار 0.6.2 — ترتيب الحجوزات بالأولوية، ألوان الحالات، وتنبيهات «بانتظار اعتمادك»

**التاريخ:** 2026-10-11
**الصفحات:** `/[locale]/owner/bookings` (وبوابة المطوّر)، الشاشة الرئيسية للبوابة `/[locale]/owner`، وزر التنبيهات في رأس البوابة

## المشكلة

- صفحة الحجوزات تعرض المعاملات بترتيب الإدخال، فتضيع طلبات الحجز التي تحتاج اعتماد المالك بين الحجوزات المؤكدة والمنتهية والملغاة.
- الحالات كلها بلون واحد تقريباً، ولا يُفرَّق بصرياً بين «بانتظار الاعتماد» و«مؤكد» و«ملغى».
- لا يوجد تنبيه للمالك في الشاشة الرئيسية ولا في رأس الصفحة بأن هناك عقداً أو طلب حجز ينتظر اعتماده. كان عليه أن يفتح صفحة العقار ليكتشف ذلك.

## الحل

### 1. ترتيب الحجوزات بالأولوية

في صفحة الحجوزات (الجدول العام وتبويب الإقامات اليومية، على الشاشة الكبيرة والجوال) تُرتَّب المعاملات هكذا:

| الأولوية | المجموعة         | الحالات                                                                                  | الترتيب داخل المجموعة |
| -------- | ---------------- | ---------------------------------------------------------------------------------------- | --------------------- |
| 1        | بانتظار الاعتماد | `request_pending`، `pending_manager_approval`، `awaiting_approval`، وحجز عربون `pending` | الأقرب تاريخاً أولاً  |
| 2        | تحتاج إجراء      | `requested`، `payment_pending`                                                           | الأقرب تاريخاً أولاً  |
| 3        | مقيم الآن / ساري | `checked_in`، والحجز المؤقت `active`                                                     | الأقرب تاريخاً أولاً  |
| 4        | قادم             | `confirmed`، `paid`، `pre_arrival`، `scheduled` (وأي حالة غير معروفة)                    | الأقرب تاريخاً أولاً  |
| 5        | منتهٍ            | `checked_out`، `closed`، `converted`، `completed`                                        | الأحدث أولاً          |
| 6        | ملغى / مرفوض     | `cancelled`، `expired`، `no_show`، `payment_failed`، `rejected`، `released`، `void`      | الأحدث أولاً          |

- التاريخ المستخدم: موعد المعاينة، أو التاريخ المفضّل، أو بداية الحجز، أو تاريخ الوصول، أو تاريخ انتهاء الحجز المؤقت، أيها وُجد أولاً. الصفوف بلا تاريخ تأتي في آخر مجموعتها.
- الصفوف التي تحتاج اعتماداً تُميَّز بشريط برتقالي على جانبها وخلفية فاتحة.
- يظهر أعلى القائمة شريط: «N معاملة بانتظار الاعتماد — تظهر أولاً في القائمة».

### 2. لون لكل حالة

| اللون        | المعنى                                 |
| ------------ | -------------------------------------- |
| برتقالي داكن | بانتظار الاعتماد                       |
| كهرماني      | ينتظر دفعاً أو إجراءً                  |
| أخضر         | مؤكد، مدفوع، مقيم الآن                 |
| أزرق         | موعد مجدول (معاينة)                    |
| رمادي        | منتهٍ أو محوَّل                        |
| أحمر         | ملغى، مرفوض، منتهي الصلاحية، فشل الدفع |

- اللون نفسه يُستخدم في الجدول وبطاقات الجوال وبطاقات الإقامات اليومية.
- أُصلح خلل سابق: الحالات الملغاة كانت تُعطى نمط `ops-status--negative` غير الموجود في CSS فتظهر بلا لون.

### 3. «بانتظار اعتمادك» في الشاشة الرئيسية

لمن يدير عقارات (المالك والمطوّر):

- **التنبيهات أعلى الشاشة الرئيسية** تبدأ بتنبيهَي الاعتماد، بلون برتقالي:
  - «N عقد بانتظار اعتمادك»: يفتح العقد مباشرة إن كان واحداً، وإلا ينتقل إلى قائمة «بانتظار اعتمادك».
  - «N طلب حجز بانتظار الاعتماد»: يفتح صفحة الحجوزات.
- **قائمة «بانتظار اعتمادك»** قبل المؤشرات: حتى 6 بنود، الأقدم أولاً. لكل بند: نوعه (عقد إيجار، عقد بيع، طلب حجز)، الرقم المرجعي، العقار والوحدة، الطرف، تاريخ البداية، وزر «فتح للاعتماد».
  - العقد يفتح قسم العقود في صفحة العقار على هذا العقد (`?section=contracts&focus=…`) حيث زر «اعتماد العقد».
  - طلب الحجز يفتح قسم الحجوزات في صفحة العقار حيث زرّا «اعتماد الحجز» و«رفض».
- إن تعذّر التحميل خلال 2.5 ثانية تُعرض الشاشة الرئيسية بدون القائمة، ولا تتعطل.

### 4. زر التنبيهات في رأس البوابة

- جرس جديد في رأس بوابتَي المالك والمطوّر، عليه عدد البنود المنتظرة.
- يفتح لوحة فيها حتى 12 بنداً بنفس الروابط، ورابط «كل الحجوزات».
- يتحدّث عند فتح الصفحة، وعند فتح اللوحة، وبعد أي اعتماد أو رفض من صفحة العقار، وعند تحديث لوحة العمليات. لا يعتمد على تبديل التبويب، التزاماً بسياسة الجلسة في 0.4.88.

### 5. من يرى ماذا

| البند           | الصلاحية المطلوبة                        | النطاق                                                            |
| --------------- | ---------------------------------------- | ----------------------------------------------------------------- |
| العقود المنتظرة | `contract.sign`                          | طلب اعتماد `pending` أو `on_hold`، والعقد ليس `void` ولا `signed` |
| طلبات الحجز     | `stay.booking.manage` و`contract.create` | حجوزات الإقامة بحالة `request_pending`                            |

حساب المالك المحصور بعقاراته لا يرى إلا عقاراته. القراءة داخل نطاق المؤسسة (RLS) كبقية البوابة.

## التحقق

- **اختبارات الوحدة:** 4 اختبارات للأولوية: تحديد ما يحتاج اعتماداً، ترتيب المجموعات الست، الترتيب داخل المجموعة (الأقرب أولاً للمفتوحة، والأحدث أولاً للمنتهية)، واللون لكل مجموعة. ناجحة.
- **بقية الاختبارات:** ناجحة، عدا فشلين قديمين معروفين لا علاقة لهما بهذا الإصدار (`next-write-route-policy` و`proxy-canonical-host`).
- **فحص الأنواع وPrettier:** ناجحة. **ESLint** على الملفات المعدّلة: لا أخطاء في التغييرات. يبقى خطآن قديمان في كود حسابي (Hisaby) داخل `operations-console.tsx`.
- **استعلام قراءة فقط على قاعدة الإنتاج** بنفس شروط `loadPendingApprovals`: يعمل، ويُرجع حالياً طلبَي حجز بانتظار الاعتماد (`ST-FE61E6C8` و`ST-6C2A8BBC`، مبنى النور) ولا عقود منتظرة.

## ملاحظات

- الترتيب يطبَّق على العرض فقط، ولا يغيّر البيانات ولا التصفية ولا البحث.
- طلبات الحجز تظهر في التنبيهات لأن اعتمادها ينشئ عقد الإيجار (0.6.0). العقد الذي ينشئه مدير بلا `contract.sign` يظهر لمن يملك هذه الصلاحية.
- الجرس العام في رأس الموقع (تنبيهات الإقامة) مخفي داخل البوابات كما كان. جرس الاعتماد خاص بالبوابة.
