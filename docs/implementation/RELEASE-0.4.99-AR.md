# الإصدار 0.4.99 — عربون حجز منفصل للتأجير والشراء، وتعديل بيانات الإيجار اليومي من صفحة تعديل العقار

الصفحة: `/owner/properties/[propertyId]/edit` (وكذلك `/developer/...`)، المكوّن `PropertyWizard`.

## 1. عربون حجز خاص للتأجير وعربون خاص للشراء

في الخطوة 2 «الوحدات»، لكل وحدة تظهر حقول العربون حسب أنماط العرض المختارة للوحدة:

| نمط العرض          | الحقل الظاهر                                                                    |
| ------------------ | ------------------------------------------------------------------------------- |
| إيجار شهري أو سنوي | «عربون حجز التأجير» — المبلغ الذي يدفعه العميل عند «أريد التأجير»               |
| بيع                | «عربون حجز الشراء» — المبلغ الذي يدفعه العميل عند «أريد الشراء»                 |
| الاثنان معاً       | الحقلان معاً، ولكل منهما مبلغه المستقل                                          |
| إيجار يومي         | ملاحظة: عربون الإقامة اليومية يُضبط في «إعدادات الإيجار اليومي» (القسم 2 أدناه) |

- عربون التأجير هو العربون الحالي للوحدة (`units.deposit_minor`) دون تغيير.
- عربون الشراء جديد. للوحدات القديمة يُملأ الحقل مبدئياً بالعربون الحالي، فلا يتغير شيء حتى يعدّله المالك.
- إذا لم يُحدَّد عربون الشراء يُستخدم عربون التأجير للشراء أيضاً (نفس السلوك السابق).
- مسح حقل عربون الشراء وحفظ العقار يحذف المبلغ الخاص ويعود الشراء لاستخدام عربون التأجير.

أين يظهر المبلغ الصحيح:

- **صفحة العقار العامة:** إذا كانت الوحدة معروضة للتأجير والشراء معاً يظهر سطران: «عربون حجز التأجير» و«عربون حجز الشراء»؛ وإذا كانت لنوع واحد يظهر «مبلغ الضمان (العربون)» بمبلغ ذلك النوع.
- **صفحة الحجز** (`/book/[unitId]`): المبلغ يتغير حسب اختيار العميل «أريد التأجير» أو «أريد الشراء».
- **الخادم:** عند إنشاء الحجز أو الرجوع لحجز غير مدفوع يُحسب العربون من جديد حسب نوع الحجز، فلا يمكن دفع عربون التأجير لحجز شراء أو العكس.
- **صفحة إدارة العقار:** البطاقة الرئيسية تعرض العربونين، وتنبيه «يحتاج انتباهك» يذكّر بالعربون الناقص منهما.

## 2. لوحة «إعدادات الإيجار اليومي» داخل صفحة التعديل

لم يكن في صفحة التعديل أي حقل لبيانات الإقامة اليومية للوحدات المنشورة (عدد الضيوف وغيره). الآن، في آخر الخطوة 2 «الوحدات»، تظهر لوحة «إعدادات الإيجار اليومي» فيها بطاقة لكل وحدة لها إعداد إقامة يومية، مع حالة النشر ورابط صفحة الإقامة العامة:

- **الضيوف والمدة:**
  - الحد الأقصى للضيوف في المبيت (حتى 999)؛
  - الحد الأقصى للضيوف في الإقامة بدون مبيت؛
  - الحد الأدنى والأقصى لعدد الليالي.
- **أوقات الدخول والخروج:**
  - وقت الدخول؛
  - وقت الخروج للإقامة بدون مبيت؛
  - وقت الخروج للمبيت؛
  - الحجز الفوري (تأكيد الحجز دون موافقة المالك).
- **الأسعار والعربون:**
  - سعر الليلة (إلزامي)؛
  - سعر نهاية الأسبوع؛
  - سعر الإقامة بدون مبيت؛
  - سعر المبيت فقط؛
  - مبلغ التأمين (العربون) للإقامة اليومية.

طريقة الحفظ:

- زر «حفظ إعدادات الإيجار اليومي» في كل بطاقة يحفظ تلك الوحدة فوراً، دون الحاجة لحفظ العقار كاملاً.
- بعد الحفظ تظهر رسالة «تم الحفظ. تظهر التغييرات في صفحة الإقامة خلال دقائق.»
- الضغط على Enter داخل حقول اللوحة لا يرسل نموذج العقار.
- رابط «الإعدادات المتقدمة: السياسات والتعليمات والنشر» يفتح صفحة إعداد الإيجار اليومي لهذا العقار لباقي الإعدادات.
- إذا كانت الوحدة معروضة للإيجار اليومي ولم يُنشأ لها إعداد بعد، تظهر رسالة توضيحية وزر «ابدأ إعداد الإيجار اليومي».

## 3. إصلاح: الوحدات اليومية كانت تتحول إلى إيجار شهري عند الحفظ

- صفحة التعديل لم تكن تقرأ أنماط العرض المحفوظة للوحدة (`units.offering_modes`)، فكانت تستنتجها من غرض الإدراج القديم.
- النتيجة: حفظ عقار وحدته «إيجار يومي» من صفحة التعديل كان يعيدها إلى «إيجار شهري».
- الآن تُقرأ الأنماط المحفوظة كما هي، ويُستخدم الاستنتاج فقط للوحدات القديمة التي ليس لها أنماط محفوظة.

## 4. رفع حدود عدد الضيوف في الإعداد

- `maxGuests` و`maxAdults` و`maxChildren` و`dayUseMaxGuests` و`overnightMaxGuests` أصبحت حتى 999 في إعداد الإقامة وملفها، بما يتوافق مع حد الحجز (999) في 0.4.98.

## ملاحظات تقنية

- **لا ترحيلات قاعدة بيانات.** عربون الشراء يُخزَّن في `stay_policies` (النوع `other`، الرمز `unit_deposit:sale:{unitId}`) مع إصدارات (أرشفة القديم وإضافة جديد)، بنفس أسلوب الشروط والترويسة.
- ملفات جديدة:
  - `apps/web/src/lib/unit-sale-deposit-neon.ts`: قراءة وكتابة عربون الشراء (خادم فقط)؛
  - `apps/web/src/lib/booking-deposit.ts`: الدالة `depositForMode()` لاختيار العربون حسب التأجير/الشراء؛
  - `apps/web/src/lib/property-stay-settings.ts`: نوع بيانات لوحة الإيجار اليومي؛
  - `apps/web/src/components/property-stay-settings-panel.tsx`: اللوحة.
- `packages/contracts`: حقل `saleDeposit` في `createUnitSchema` (‏`null` يحذفه، وعدم إرساله يبقيه كما هو) وفي `publicUnitDetailSchema`.
- `stay-setup-neon.ts`: الدالة `loadPropertyStaySettingsOnNeon()` تحمّل ملف الإقامة وسعر الخطة الأساسية ورابط النشر لكل وحدة في العقار.
- الحفظ من اللوحة يستخدم الواجهة الحالية `POST /api/owner/stays/setup` (‏`update_profile` ثم `upsert_rate_plan`) بنفس الصلاحيات.
- `load-property-neon.ts`: قراءة `offering_modes` وعربون الشراء لكل وحدة.
- `create-property-neon.ts`: حفظ عربون الشراء عند الإنشاء والتعديل.
- `public-lease-booking-neon.ts`: العربون يُحسب حسب نوع الحجز.
- صفحة الحجز ومكوّن `LeaseDepositCheckout`: مبلغ لكل نوع (`depositByMode`).
