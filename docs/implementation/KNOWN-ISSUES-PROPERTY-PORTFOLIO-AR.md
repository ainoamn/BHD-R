## السبب الجذري (تحليل)

### CSRF مزدوج المصدر على نفس الكوكي `bhd_r_csrf`

- مسارات Next (`/api/owner/*`) تتحقق بـ `CSRF_SECRET` على **Vercel** عبر `requireLiveSession({ requireCsrf: true })`.
- مسارات Nest (`/api/backend/v1/*`) تتحقق بـ `CSRF_SECRET` على **Render**.
- `getCsrfToken()` كان يفضّل سكّ `/api/auth/csrf` (Next) لكل شيء، بما فيها `browserMutation` نحو Nest.
- إذا اختلف السرّان، أو إذا أعاد Nest كتابة الكوكي بعد رفع وسائط، يفشل التحقق: إما `csrf_rejected` على Next أو `CSRF validation failed` على Nest.
- واجهة الاستعادة تعتمد `browserMutation`؛ عند فشل Nest أو شكل خطأ غير `{ error.messageAr }` تظهر **Request failed**.

### قائمة الأرشيف

- `GET /v1/owner/properties` يعيد كل الحالات بما فيها `archived` بلا تصفية افتراضية.
- واجهة العمليات تعرض الكل عندما يكون فلتر الحالة فارغاً.

### الحذف النهائي

- موجود فقط أرشفة / استعادة (`property.archive`)؛ لا مسار purge/delete للعقار المؤرشف.
