## أين يضبط المالك؟

1. **الضبط** (`/owner/settings` أو `/developer/settings`)
   - تبويبات: تأجير يومي · إيجار طويل الأجل · شراء
   - لكل نوع: اعتماد الحجز، العقد، الدفع، التوقيع الإلكتروني، وأتمتة المعاينة (للإيجار/الشراء)
   - بطاقة مستندات المستأجر المطلوبة (خمسة مسارات)
2. **شروط العقار** — نفس السياسات يمكن تخصيصها لعقار واحد
3. **الفريق** — قدرات منفصلة: يومي فقط / طويل الأجل فقط / إدارة المعاينات

## أنواع العقود الثلاثة

| النوع            | الرمز في النظام | أمثلة الضبط                                           |
| ---------------- | --------------- | ----------------------------------------------------- |
| تأجير يومي       | `daily`         | اعتماد حجز، عقد تلقائي، تعديل تواريخ، توقيع إلكتروني  |
| إيجار طويل الأجل | `rent`          | حجز، عقد، مستندات، إقرار، حقول مؤجّلة، معاينة تلقائية |
| شراء             | `sale`          | عربون، عقد، توقيع إلكتروني، معاينة تلقائية            |

التخزين: `stay_policies` بالكود  
`approval_policy:{daily|rent|sale}:{propertyId|org}`  
مع الرجوع للسياسة القديمة المشتركة إن وُجدت.

## مستندات المستأجر الذكية

- مسارات: شخصي عماني / شخصي وافد / شركة / مفوّض عماني / مفوّض وافد
- عند إعداد العقد يُقترح تلقائياً حسب النوع والجنسية (وجنسية المفوّض للشركات)
- API: `GET/PUT /api/owner/lease-document-rules`

## أتمتة المعاينة

- عند تفعيل «تأكيد الموعد تلقائياً» في سياسة الإيجار أو الشراء
- وإن اختار الزائر وقتاً مفضّلاً في النموذج
- يعتمد النظام الموعد ويُصدر بطاقة الزيارة ويُبلّغ المالك والموظف/الحارس
- إيقاف الخيار = جدولة يدوية من مكتب المعاينات كما سابقاً
- مسار النموذج العام: `POST /api/public/guest-viewing-requests`

## تحقق على الإنتاج

- [ ] الضبط → ثلاث تبويبات عقود؛ حفظ كل نوع على حدة
- [ ] شروط عقار → تخصيص سياسة لعقار واحد ثم «العودة لسياسة المؤسسة»
