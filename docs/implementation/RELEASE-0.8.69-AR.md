# الإصدار 0.8.69 — محور محاسبة عالمي في `/owner/accounting`

**التاريخ:** 2026-10-18  
**الحالة:** جاهز للرفع

## المشكلة

صفحة [`/ar/owner/accounting`](https://r.bhd-om.com/ar/owner/accounting) كانت تعرض أمانات التأمين وقائمة تشغيلية ضيقة، بينما الموقع القديم [bhd-om](https://github.com/ainoamn/bhd-om) فيه محور محاسبة كامل (دليل حسابات، قيود مزدوجة، تقارير، إقفال فترات، تدقيق). المطلوب سحب ذلك المستوى إلى BHD-R دون ترحيل قاعدة بيانات، مع الإبقاء على تكامل Hisaby للكشوفات المفصّلة.

## الحل

محور محاسبة احترافي على Neon فوق الجداول الموجودة (`ledger_accounts`, `journal_entries`, `journal_lines`, `expenses`, `workflow_events`):

1. **لوحة التحكم:** ذمم، محصّل، مصروفات، مسودات، قيود مرحّلة، عدد الحسابات، فواتير متأخرة.
2. **أمانات التأمين:** التبويب السابق كما هو (`DepositLedgerPanel`).
3. **دليل الحسابات:** تهيئة 24 حساباً (صندوق/بنوك/ذمم/تأمينات/إيرادات/مصروفات…) وإضافة حسابات يدوياً.
4. **قيود اليومية:** قيد مزدوج متوازن فقط، ترحيل/عكس، رفض الفترة المقفلة.
5. **المصروفات:** تسجيل سريع مع سجل حالات.
6. **التقارير:** ميزان مراجعة، قائمة دخل، ميزانية عمومية، تدفقات نقدية (1000/1100)، أعمار ذمم مدينة.
7. **إقفال الفترات:** عبر `workflow_events` بمعرّف UUID حتمي + `metadata` (بدون جدول جديد).
8. **التدقيق:** أحداث الحسابات والقيود والمصروفات والفترات.
9. رابط Hisaby يبقى للكشوفات المفصّلة خارج المنصة.
