# الإصدار 0.4.96 — سرعة التقويم وتقويم المالك الموحّد

## سبب بطء التقويم

- دوال الموقع على Vercel كانت تعمل في واشنطن (`iad1`)، وقاعدة البيانات Neon في لندن (`eu-west-2`).
- كل استعلام يعبر الأطلسي ذهابًا وإيابًا (~80 ملي ثانية)، وطلب التقويم الواحد ينفّذ 20–30 استعلامًا متتاليًا، فيستغرق عدة ثوانٍ، ويتضاعف ذلك عند أول تشغيل للدالة أو مع بطء الشبكة.
- أيضًا التقويم يبدأ التحميل بعد تحميل الصفحة نفسها في المتصفح، فيتراكم الوقتان.

## الإصلاح

- `apps/web/vercel.json`: `"regions": ["lhr1"]` — الدوال الآن في لندن بجانب قاعدة البيانات، وهي أيضًا أقرب لعُمان من واشنطن.
- تهيئة جلسة قاعدة البيانات (المؤسسة/المستخدم/الصلاحيات) أصبحت استعلامًا واحدًا بدل ستة في صفحات المالك، وبدل اثنين في الصفحات العامة.

## تقويم المالك الموحّد (`/owner/stays/calendar` و`/developer/stays/calendar`)

- تقويم واحد لكل العقارات افتراضيًا:
  - **أحمر:** يوجد حجز في ذلك اليوم (مع عدد الحجوزات).
  - **أخضر:** لا توجد حجوزات.
- الضغط على أي تاريخ يعرض حجوزات ذلك اليوم: العقار والوحدة، الضيف، الهاتف، الفترة (اليوم كاملًا / الصباحية / المسائية)، الوصول والمغادرة، المبلغ، الحالة، المرجع، وزر «تفاصيل الحجز».
- قائمة منسدلة للعقارات مع بحث (باسم العقار أو اسم الوحدة أو رمزها):
  - «كل العقارات»: التقويم الموحّد.
  - عقار محدد: التقويم يعرض حجوزاته فقط، ويظهر أسفله تقويم «الأسعار وإغلاق الأيام» لذلك العقار مع محرر اليوم كما كان.
- مسار جديد: `GET /api/owner/stays/calendar-overview?fromOn&toOn[&unitId]` (جلسة حيّة، حد أقصى 93 يومًا).
