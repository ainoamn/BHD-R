# الإصدار 0.5.9 — بيانات أقسام العقار من قاعدة البيانات لهذا العقار فقط

**التاريخ:** 2026-10-08
**الصفحة:** `/[locale]/owner/properties/[propertyId]?section=…` (وكذلك بوابة المطوّر)

## المشكلة

في الإصدار 0.5.8 صارت الأقسام تُعرض داخل صفحة العقار، لكن بقيت فيها بيانات لا تخص العقار، وتفاصيل ناقصة:

- القسم كان يستخدم لوحة العمليات العامة: تجلب سجلات المؤسسة كلها، ثم تصفّيها في المتصفح.
- العقود والتأجير والبيع والحجوزات تأتي من خادم Nest، فإذا كان نائماً لا يظهر شيء، وإذا اختلف شكل البيانات لا تعمل التصفية.
- الأعمدة كانت عامة: معرّفات بدل أسماء المستأجرين، ولا تُعرض تواريخ العقد وحالة الإيجار والمبالغ بوضوح.

## الحل

### مصدر بيانات خاص بالعقار

- **مسار جديد للقراءة فقط:** `GET /api/portal/property-records/:propertyId/:section`.
- **الأقسام المدعومة:** `bookings`، `contracts`، `leasing`، `sales`، `maintenance`، `invoices`، `accounting`.
- **مصدر البيانات:** `apps/web/src/lib/property-records-neon.ts` يقرأ من Neon مباشرة، ضمن سياق المؤسسة وصلاحيات المستخدم (`withinViewerTenant` مع RLS).
- **الصلاحية:** يتحقق المسار أولاً أن العقار يتبع مؤسسة المستخدم، وأن المالك المقيّد يملكه (`ownerPartyScope`)، وإلا يرجع 404.
- **الأدوار المسموحة:** نفس أدوار بوابة المالك والمطوّر.
- كل استعلام مقيّد بالعقار أو بوحداته، فلا تصل إلى المتصفح أي بيانات لعقار آخر.

### ما يعرضه كل قسم

| القسم               | السجلات                                                                             | الأعمدة                                                                                                   |
| ------------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| الحجوزات والمعاينات | حجوزات الإقامة اليومية + الحجوزات بالعربون + المعاينات                              | النوع، المرجع، الوحدة، العميل/الضيف، من، إلى، المبلغ، الحالة                                              |
| العقود              | كل عقود وحدات العقار بكل حالاتها (مسودة، مُرسل، موقّع، ملغى، منتهٍ)                 | رقم العقد، نوعه، الوحدة، المستأجر، بداية ونهاية الإيجار، الإيجار، تاريخ التوقيع، حالة العقد، حالة الإيجار |
| التأجير             | كل عقود الإيجار (سارية، منتهية، ملغاة، بانتظار المخالصة…)                           | العقد، الوحدة، المستأجر، من، إلى، الإيجار، التأمين، تاريخ الإلغاء، الحالة                                 |
| البيع               | صفقات البيع للعقار                                                                  | المرجع، الوحدة، المشتري، البائع، السعر المطلوب، السعر المتفق/العرض، التاريخ، الحالة                       |
| الصيانة             | طلبات صيانة وحدات العقار                                                            | الطلب، الوحدة، الفئة، الأولوية، مقدّم الطلب، تاريخ الطلب والحل، الحالة                                    |
| الفواتير            | فواتير عقود وحدات العقار                                                            | الرقم، الوحدة، المستأجر، الإصدار، الاستحقاق، الإجمالي، المدفوع، المتبقي، الحالة                           |
| الحسابات            | دفعات الإقامة الناجحة + دفعات فواتير الإيجار (إيراد) + مصروفات العقار ووحداته (صرف) | التاريخ، النوع، المرجع، الوحدة، الطرف، البيان، المبلغ (+/−)، الحالة                                       |

### واجهة القسم

- **المكوّن:** `PropertySectionRecords`، بطاقة فيها عنوان القسم وعدد السجلات وزر «تحديث».
- **ملخص مالي:** للفواتير (الإجمالي، المحصّل، المتبقي) وللحسابات (الإيرادات، المصروفات، الصافي) حسب العملة.
- **التصفية والبحث:** أزرار تصفية بالحالة مع العدد («الكل» + كل حالة موجودة فعلاً)، وبحث بالاسم أو الرقم أو الوحدة.
- **زر «فتح»:** لعقد معيّن، أو حجز إقامة، أو حجز بعربون.
- **تسميات الحالات:** أُضيفت تسميات عربية للحالات الناقصة إلى `ui-labels.ts`: العقود، الإيجار، المعاينات، البيع، المصروفات.

### الشروط والأحكام

صفحة «الشروط والأحكام» (`/properties/[id]/terms`) كانت أصلاً خاصة بالعقار. تعرض شروط العقار المخصّصة، أو الصيغة الموحدة للمؤسسة إن لم تُخصَّص له شروط، وتوضّح الصفحة ذلك. لم تتغيّر.

### إزالة ما لم يعد مستخدماً

خاصية `scopePropertyId` التي أُضيفت في 0.5.8 إلى `OperationsConsole` و`OperationsWorkspaceClient` أُزيلت، وعاد الملفان كما كانا في 0.5.7. ربط الفواتير والصيانة والمصروفات بالعقار في `portal-ops-data.ts` بقي، لأنه يفيد تصفية `?propertyId=` في الصفحات العامة.

## الملفات

- `apps/web/src/lib/property-records-neon.ts` (جديد): استعلامات الأقسام السبعة لعقار واحد.
- `apps/web/src/app/api/portal/property-records/[propertyId]/[section]/route.ts` (جديد): مسار القراءة.
- `apps/web/src/components/property-section-records.tsx` (جديد): جدول القسم والملخص والتصفية.
- `apps/web/src/components/property-manage-hub.tsx`: يعرض `PropertySectionRecords` بدل لوحة العمليات العامة.
- `apps/web/src/lib/portal-ops-data.ts`: تصدير `withinViewerTenant` و`ownerPartyScope`.
- `apps/web/src/lib/ui-labels.ts`: تسميات الحالات الجديدة.
- `apps/web/src/app/globals.css`: كتلة «Property section records» و`.pmh-badge--danger`.
- `apps/web/src/components/operations-console.tsx` و`operations-workspace-client.tsx`: إرجاع تعديلات 0.5.8.

## التحقق

- `typecheck` لتطبيق الويب: ناجح (Drizzle يتحقق من كل الجداول والأعمدة المستخدمة).
- ESLint: لا أخطاء في الملفات الجديدة والمعدّلة.
- Prettier: سليم.
- الاختبارات: لا فشل جديد (اختبارا سياسة مسارات الكتابة والنطاق كانا يفشلان قبل هذا الإصدار، ولا يظهر فيهما المسار الجديد).
- لم تُشغَّل الاستعلامات على قاعدة بيانات محلية (لا يوجد `DATABASE_URL` محلي)، والتحقق النهائي يكون على الموقع بعد النشر.
