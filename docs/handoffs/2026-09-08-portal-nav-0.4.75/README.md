# تعديل التنقل في BHD-R

الحالة: تعديل محلي جاهز للمراجعة؛ لم يُرفع إلى GitHub ولم يُنشر.

## ما تغيّر

- تبديل أقسام العمليات الـ19 من القائمة داخل الغلاف الحالي، مع تحديث العنوان وسجل الرجوع عبر History API المدعوم من Next.js.
- إبقاء محتوى صفحات المالك والمطور الفعلي داخل الغلاف المشترك: لوحة التحكم، تفاصيل العقارات والإضافة والتعديل، العقود والمعاينات، وصفحات الإقامات والتقويم والأسعار والإعداد والحجوزات وتفاصيلها.
- إزالة تخزين عناصر LayoutRouter الحية وإعادة نقلها بين حاويات مختلفة. تسجيل محتوى الصفحة الفعلي بمفتاح مسار صادر من الخادم يحافظ على مكونات النماذج عند الرجوع ويمنع خلط الاستجابات المتأخرة.
- إلغاء حد الـ12 صفحة الذي كان يتسبب في التخلص من النماذج القديمة. تبقى الصفحات المزارة في ذاكرة جلسة البوابة؛ يتزايد استهلاك الذاكرة مع عدد التفاصيل المفتوحة. لا تحفظ مسودات النماذج بعد تحديث المتصفح أو إغلاقه.
- تحميل صفحات القائمة والإضافة وروابط التفاصيل والتعديل المكتشفة تدريجيًا في الخلفية. مراقبة الروابط الجديدة، معالجة انتهاء صلاحية التحميل المسبق، وإيقاف الجدولة عند إخفاء التبويب أو مغادرة الغلاف. يبقى التحميل معتمدًا على سرعة الخادم والشبكة؛ لا توجد ضمانة أن كل سجل غير مكتشف قد حُمّل قبل أول نقرة.
- استبدال إعادة تحميل المتصفح في حفظ العقار وروابط التعديل بتنقل داخلي.
- قصر تحديث واجهة العمليات على القسم النشط، وتطبيق معاملات الرابط على القسم النشط فقط، مع قراءة تغييرات معاملات الرابط دون إعادة تركيب النموذج.
- اختبارات لتكرار مؤثرات StrictMode، تحميل مسارات القائمة، حفظ المسودات بعد أكثر من 12 صفحة، دمج تحديثات الخادم، ومنع عرض استجابة صفحة قديمة كصفحة جديدة.

## التحقق

- بناء حزم المشروع التابعة: ناجح.
- TypeScript: ناجح، بما فيه فحص الأنواع ضمن البناء النهائي.
- بناء الإنتاج النهائي: `next build --webpack` ناجح على Next.js 16.3.2 وNode.js 24.19.0، مع تحذيرات تخزين webpack المؤقت في هذه البيئة.
- نجح بناء Turbopack سابق أثناء العمل؛ عند إعادة البناء اصطدم تشغيل PostCSS بخطأ صلاحيات Node المحلي. استُخدم webpack للتحقق النهائي دون تغيير إعداد بناء المشروع.
- ESLint للملفات الأساسية المعدّلة واختبار التنقل الجديد: ناجح.
- اختبارات الوحدة: 20 ناجحة، 2 فاشلة في `next-write-route-policy.test.ts`؛ هذان الاختباران يخصان مسارات API لم يعدّلها هذا العمل. يرصدان متطلبات requireLiveSession/CSRF وclientSafeErrorCode. لم تُخفَ هذه الإخفاقات ولم تُعدّل مساراتها.
- اختبارات التنقل الستة الجديدة ناجحة. اختبارات ذاكرة العمليات الثلاثة ناجحة، بعد مواءمة توقعات الاختبار القديمة مع مدد 5 و30 دقيقة الموجودة أصلًا في التنفيذ.
- أُضيف اختبار Playwright لحفظ اختيار نموذج العقار بعد المرور بأكثر من 12 قسمًا، والتحقق من عدم إنشاء طلب document جديد. لم يُشغّل: منع نظام المراجعة التلقائية تشغيل خادم الاختبار المحلي حتى بعد منح إذن الشبكة؛ لم يذكر سببًا تفصيليًا سوى طلب موافقة تمنعها سياسة البيئة.

## التطبيق

الملف `BHD-R-navigation.patch` يحتوي التغييرات كاملة بما فيها الملفات الجديدة.

من جذر نسخة المستودع المراد تعديلها:

```sh
git apply --check /path/to/BHD-R-navigation.patch
git apply /path/to/BHD-R-navigation.patch
```

بُني التعديل على commit `9a26a35ad7a60bbed089f8d0090e7e2029df0891`، وفُحص تطبيقه دون تعارض على main الأحدث `556388d1a25404e6ddde5afce91769b64b143a41` (الإصدار 0.4.74). التحديث الجديد يخص الصفحة العامة وإعداد مهلة البناء ولا يتداخل مع ملفات التعديل.

بعد التطبيق يلزم اختبار المتصفح، بما فيه نموذج إضافة العقار والرجوع إليه، تعديل عقار موجود وحفظه، التنقل بين تفاصيل حجزين، تغييرات معاملات الروابط، واستخدام زرّي الرجوع والتقدم، ثم الدمج والنشر بالطريقة المعتادة. الصفحات المسجّلة تظهر داخل الغلاف بعد hydration؛ يلزم التحقق من أول تحميل أيضًا.
