## 1. الخلاصة التنفيذية

**BHD R** منصة عمانية ثنائية اللغة (عربي / إنجليزي) لإدارة وتسويق العقارات والوحدات، العقود الإلكترونية، الفواتير والمدفوعات، الصيانة، والتقارير. الحرف **R** يعني **Real Estate Management — إدارة العقارات**.

بُنيت من الصفر كـ **Modular Monolith** داخل Monorepo، بهوية BHD الموحدة، دون دمج شيفرة النظام القديم `bhd-om`. الهدف: نفس السلوك التشغيلي المطلوب (عقار ← وحدة ← نشر ← حجز ← عقد ← توقيع ← إيجار ← فاتورة ← دفع ← صيانة)، بتقنيات أخف وأأمن وأوضح.

| البعد    | القرار                                                                              |
| -------- | ----------------------------------------------------------------------------------- |
| المنتج   | منصة عقارية متعددة الأدوار مع سوق عام                                               |
| الهوية   | BHD Identity OIDC (`bhd-r`) عبر `/api/auth/bhd/*` + جلسات Host-only `bhd_r_session` |
| الواجهة  | Next.js 16 + React 19 + Tailwind 4 + next-intl                                      |
| الـ API  | NestJS 11 على Fastify                                                               |
| البيانات | PostgreSQL 17 + PostGIS + Drizzle + RLS                                             |
| الخلفية  | Worker + Redis/BullMQ + Outbox                                                      |
| الوسائط  | S3 خاص للأصل + مشتقات عامة بعلامة مائية                                             |
| المال    | NUMERIC / Decimal — لا Float                                                        |
| اللغات   | ar (RTL) و en (LTR)                                                                 |
| العملات  | OMR, BHD, KWD, AED, SAR, QAR, USD + قابلية إضافة                                    |

## 2. أهداف المنتج

1. تمكين إدارة المنصة والمالك والمطور من إدارة محفظة عقارية منظمة.
2. عرض الوحدات المتاحة فقط للجمهور بعد اكتمال النشر والتوفر.
3. إدارة دورة الإيجار حتى التوقيع الإلكتروني والفوترة والتحصيل.
4. منح المستأجر بوابة مستقلة لعقوده وفواتيره وطلبات الصيانة.
5. عزل المؤسسات (tenants) بصلاحيات مركزية وRLS.
6. التوافق مع هوية ومنتجات BHD الأخرى (ألوان، دخول موحد، أسلوب تشغيل).
7. قابلية التوسع الخليجي والدولي عبر Country Packs.

### 4.1 إضافة العقار

1. من لوحة المالك أو المطور أو المنصة يفتح معالج العقار (`property-wizard`).
2. يختار **فردي** (`single_unit`) أو **متعدد الوحدات** (`multi_unit`).
3. الفردي ينشئ وحدة واحدة تلقائياً؛ المتعدد يدخل تفاصيل كل وحدة (مساحة، غرف، إيجار، مرافق…).
4. تُرفع الصور عبر upload intent إلى التخزين الخاص، ثم يعالجها Worker (إعادة ترميز، إزالة EXIF، علامة مائية، AVIF/WebP).
5. لا يكفي زر النشر: الظهور العام يتطلب اكتمال البيانات + حالة توفر مشتقة `available`.

#### صفحة إدارة العقار (0.4.97)

صفحة العقار في لوحة المالك/المطوّر (`/owner/properties/[id]`) مرتبة من الأعلى للأسفل:

1. **شريط «إجراءات هذا العقار»**: ثابت دائماً في الأعلى أثناء التمرير. فيه: الرجوع للمحفظة، تعديل العقار، عرض للجمهور، الإقامة اليومية، الحجوزات، العقود، الشروط والأحكام، التأجير، البيع، الصيانة، الفواتير، الحسابات.
2. **بطاقة العقار**: صورة الغلاف، الحالة، النوع، الرقم المتسلسل، العنوان، المالك، العربون، المساحة، سنة البناء.
3. **أرقام سريعة**: الوحدات والمنشورة منها، الإقامات النشطة، العقود، الصور.
4. **الحجوزات اليومية، والعقود والإيجارات، والوحدات** (السعر، حالة النشر، الإشغال)، وبجانبها «يحتاج انتباهك» والمالية.
5. **إجراءات حساسة** في الأسفل: أرشفة/استعادة وحذف نهائي.

التفاصيل: [implementation/RELEASE-0.4.97-AR.md](./implementation/RELEASE-0.4.97-AR.md).

#### عرض العقارات وإدارة العقارات (0.5.7)

- «العقارات» في الشريط الجانبي قائمة منسدلة بخيارين: **عرض العقارات** (`/{portal}/properties`) و**إدارة العقارات** (`/{portal}/properties?mode=manage`).
- **العرض:** القائمة بلا عمود إجراءات وبلا أزرار في الصفوف.
- **الإدارة:** زر «إدارة العقار» أو «إدارة الوحدة» لكل صف يفتح صفحة إدارة العقار، وسهم الرجوع فيها يعيد إلى «إدارة العقارات».
- صفحات العقار الفردي تُحسب ضمن «إدارة العقارات» في الشريط الجانبي، ومعالج الإضافة ضمن «عرض العقارات».
- التفاصيل: [implementation/RELEASE-0.5.7-AR.md](./implementation/RELEASE-0.5.7-AR.md).

#### أقسام العقار داخل صفحة العقار (0.5.8)

- أزرار «الحجوزات والمعاينات»، «العقود»، «التأجير»، «البيع»، «الصيانة»، «الفواتير»، «الحسابات» في شريط إجراءات العقار تعرض القسم **داخل صفحة العقار** (`/{portal}/properties/[id]?section=<القسم>`) بدل الانتقال لصفحة القسم العامة.
- القسم يُعرض بلوحة العمليات نفسها مقيّدة بالعقار (`scopePropertyId` و`scopeUnitIds`): السجلات والمؤشرات وطوابير العمل وقوائم نموذج الإضافة لهذا العقار ووحداته فقط.
- اسم العقار في الشريط يعيد إلى النظرة العامة.
- الفواتير (عبر العقد ثم الوحدة) والصيانة (عبر الوحدة) والمصروفات تحمل الآن `propertyId` و`unitId` في بيانات Neon.
- التفاصيل: [implementation/RELEASE-0.5.8-AR.md](./implementation/RELEASE-0.5.8-AR.md).

#### بيانات أقسام العقار من قاعدة البيانات (0.5.9)

- تصفية بالحالة، وبحث، وملخص مالي للفواتير والحسابات، وزر «فتح» للعقد أو الحجز.

#### اعتماد الحجز → العقد → التأجير، والعقود اليدوية (0.6.0)

- **الحجوزات:** «اعتماد الحجز» لطلبات `request_pending` يعيد فحص التواريخ، ويُنشئ قفل الحجز، ويجعل الحجز «مؤكّد». ثم يُنشئ عقد إيجار `CTR-YYYY-NNNNNN` وإيجاراً لفترة الحجز. «رفض» يلغي الطلب ويحرّر التواريخ.
- **التوقيع:**
  - توقيع المستأجر يأتي من قبوله للشروط والأحكام عند الحجز.
  - توقيع المالك يضعه النظام باسم المستخدم إن كان يملك `contract.sign`. وإلا يصبح العقد «بانتظار اعتماد المدير» مع طلب اعتماد مُسنَد لمالك المؤسسة، ويعتمده المالك بزر «اعتماد العقد».
- **التأجير:** حالة «مؤجر / يبدأ لاحقاً / انتهت المدة»، ورقم العقد رابط إلى قسم العقود.
- **العقود اليدوية:** «عقد تأجير يدوي» في قسم التأجير (يمنع تداخل الإيجارات)، و«عقد بيع يدوي» في قسم البيع (صفقة بيع وعقد مرتبط).
- **المسار:** `POST /api/owner/properties/:propertyId/records` (`property-contracts-neon.ts`).
- التفاصيل: [implementation/RELEASE-0.6.0-AR.md](./implementation/RELEASE-0.6.0-AR.md).

#### تسجيل عقد الإيجار بشروطه المالية (0.6.1)

- **النموذج:** «+ عقد تأجير يدوي» في قسم التأجير، بأقسام bhd-om: بيانات العقد، المستأجر (فرد أو شركة، أو من دفتر العناوين)، الوحدة والعدادات، الإيجار والمدة، الضرائب والرسوم، التأمين، جدول الدفع، والمبالغ الإضافية والخصومات.
- **الحساب** (`lease-terms.ts`، مشترك بين المتصفح والخادم):
  - الإيجارات من الجدول، والأيام الزائدة بالتناسب.
  - القيمة المضافة 5% مع الإيجار أو بشيكات منفصلة.
  - البلدية 3% من الإيجارات، ورسوم التسجيل، وضريبة أخرى اختيارية.
  - الإضافات والخصومات بحسب التكرار والمدة، وخصم فترة السماح (الإيجار ÷ 30 × الأيام).
  - التأمين منفصل عن إجمالي العقد.
- **الحفظ:**
  - الشروط كاملة في `payloadSnapshot.leaseTerms`، وبيانات المستأجر في `payloadSnapshot.tenantDetails`.
  - الإيجار الشهري ويوم الاستحقاق في `leases`.
  - الشيكات في `cheques` بحالة «بانتظار المراجعة».
- **العرض:** عمود «إجمالي العقد» في التأجير، وزر «التفاصيل المالية» في التأجير والعقود.
- التفاصيل: [implementation/RELEASE-0.6.1-AR.md](./implementation/RELEASE-0.6.1-AR.md). المرجع الدائم (الحقول، شكل الطلب، ما يُحفظ، الأخطاء): [implementation/LEASE-REGISTRATION-AR.md](./implementation/LEASE-REGISTRATION-AR.md).

#### إلغاء الحجز وتعديل تواريخه من صفحة الضيف (0.6.7)

- **تعديل التواريخ:** يعدّل الحجز نفسه، فيبقى رقمه وحالته.
  - التقويم يعرض الأيام الشاغرة فقط، مع أيام الحجز الحالي.

- **قاعدة السعر (`stayRescheduleCharge`):**
  - المبلغ المعتمد = الأعلى بين سعر التقويم للتواريخ الجديدة وسعر الحجز الأصلي.

  - الحجز المدفوع لا يُعدَّل إلى سعر أعلى إلكترونياً.
- **الخادم:** `POST /api/public/stays/guest/reschedule`، بمعاينة (`confirm: false`) ثم تأكيد ينقل القفل ويسجّل التعديل.

- يظهر ذلك في: صفحة العقار العامة، وتقويم المالك، وصفحة تفاصيل الحجز للمالك (صف «نطاق الحجز» وحالة الفترة الأخرى وسعرها).

  - الأوقات: الدخول، والخروج لكل نوع إقامة، والحجز الفوري؛
  - الأسعار: الليلة، ونهاية الأسبوع، وبدون مبيت، والمبيت فقط، ومبلغ التأمين.
- كل بطاقة تُحفظ مستقلة عبر `POST /api/owner/stays/setup`، مع رابط للإعدادات المتقدمة (السياسات والتعليمات والنشر).
- إصلاح: صفحة التعديل أصبحت تقرأ `units.offering_modes`، فلا تتحول الوحدات اليومية إلى «إيجار شهري» عند الحفظ.

### 4.4 تفعيل المستأجر

- النظام يمنح **اسم مستخدم** + **رابط/رمز تفعيل أحادي الاستخدام** داخل BHD Identity.
- لا تُرسل كلمة مرور دائمة بالبريد (قرار أمني معتمد).
- بعد التفعيل يدخل المستأجر لوحته فقط.

### 4.5 الممثلون والمشرفون

- المالك (فرد أو شركة) يعين مشرفين/ممثلين ضمن حدود الباقة (`entitlements`) وresource grants.
- كل ممثل يرى فقط الموارد الممنوحة له.

### 4.6 المالية والصيانة والتقارير

- فواتير بترقيم متزامن لكل مؤسسة/سنة، ومبالغ Decimal.
- مدفوعات مع `Idempotency-Key` وwebhooks موقّعة وunique `(provider, event_id)`.
- صيانة: بلاغ → تعيين → تقدم → إغلاق.
- تقارير من بيانات حقيقية عبر وحدة `reports` (ليست محاكاة).
