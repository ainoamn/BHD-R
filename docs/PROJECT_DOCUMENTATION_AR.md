## 1. الخلاصة التنفيذية

**BHD R** منصة عمانية ثنائية اللغة (عربي / إنجليزي) لإدارة وتسويق العقارات والوحدات، العقود الإلكترونية، الفواتير والمدفوعات، الصيانة، والتقارير. الحرف **R** يعني **Real Estate Management — إدارة العقارات**.

بُنيت من الصفر كـ **Modular Monolith** داخل Monorepo، بهوية BHD الموحدة، دون دمج شيفرة النظام القديم `bhd-om`. الهدف: نفس السلوك التشغيلي المطلوب (عقار ← وحدة ← نشر ← حجز ← عقد ← توقيع ← إيجار ← فاتورة ← دفع ← صيانة)، بتقنيات أخف وأأمن وأوضح.

| البعد    | القرار                                                                              |
| -------- | ----------------------------------------------------------------------------------- |
| المنتج   | منصة عقارية متعددة الأدوار مع سوق عام                                               |
| الهوية   | BHD Identity OIDC (`bhd-r`) عبر `/api/auth/bhd/*` + جلسات Host-only `bhd_r_session` |
| الواجهة  | Next.js 16 + React 19 + Tailwind 4 + next-intl                                      |
| الـ API  | NestJS 11 على Fastify                                                               |
| البيانات | PostgreSQL 17 + PostGIS + Drizzle + RLS                                             |
| الخلفية  | Worker + Redis/BullMQ + Outbox                                                      |
| الوسائط  | S3 خاص للأصل + مشتقات عامة بعلامة مائية                                             |
| المال    | NUMERIC / Decimal — لا Float                                                        |
| اللغات   | ar (RTL) و en (LTR)                                                                 |
| العملات  | OMR, BHD, KWD, AED, SAR, QAR, USD + قابلية إضافة                                    |

## 2. أهداف المنتج

1. تمكين إدارة المنصة والمالك والمطور من إدارة محفظة عقارية منظمة.
2. عرض الوحدات المتاحة فقط للجمهور بعد اكتمال النشر والتوفر.
3. إدارة دورة الإيجار حتى التوقيع الإلكتروني والفوترة والتحصيل.
4. منح المستأجر بوابة مستقلة لعقوده وفواتيره وطلبات الصيانة.
5. عزل المؤسسات (tenants) بصلاحيات مركزية وRLS.
6. التوافق مع هوية ومنتجات BHD الأخرى (ألوان، دخول موحد، أسلوب تشغيل).
7. قابلية التوسع الخليجي والدولي عبر Country Packs.

## 4. كيف يعمل البرنامج؟ (رحلة من طرف لطرف)

```mermaid
flowchart TD
  A[إضافة عقار فردي أو متعدد] --> B[إنشاء وحدات + صور]
  B --> C[نشر Listing]
  C --> D{الوحدة available؟}
  D -->|نعم| E[ظهور في البحث العام]
  D -->|held / reserved / leased / maintenance| F[اختفاء من البحث]
  E --> G[Hold / حجز]
  G --> H[عقد + توقيع إلكتروني]
  H --> I[تفعيل Lease]
  I --> J[دعوة مستأجر + Username]
  I --> K[فواتير + مدفوعات]
  I --> L[صيانة وتقارير]
```

### 4.1 إضافة العقار

1. من لوحة المالك أو المطور أو المنصة يفتح معالج العقار (`property-wizard`).
2. يختار **فردي** (`single_unit`) أو **متعدد الوحدات** (`multi_unit`).
3. الفردي ينشئ وحدة واحدة تلقائياً؛ المتعدد يدخل تفاصيل كل وحدة (مساحة، غرف، إيجار، مرافق…).
4. تُرفع الصور عبر upload intent إلى التخزين الخاص، ثم يعالجها Worker (إعادة ترميز، إزالة EXIF، علامة مائية، AVIF/WebP).
5. لا يكفي زر النشر: الظهور العام يتطلب اكتمال البيانات + حالة توفر مشتقة `available`.

#### صفحة إدارة العقار (0.4.97)

صفحة العقار في لوحة المالك/المطوّر (`/owner/properties/[id]`) مرتبة من الأعلى للأسفل:

1. **شريط «إجراءات هذا العقار»**: ثابت دائماً في الأعلى أثناء التمرير. فيه: الرجوع للمحفظة، تعديل العقار، عرض للجمهور، الإقامة اليومية، الحجوزات، العقود، الشروط والأحكام، التأجير، البيع، الصيانة، الفواتير، الحسابات.
2. **بطاقة العقار**: صورة الغلاف، الحالة، النوع، الرقم المتسلسل، العنوان، المالك، العربون، المساحة، سنة البناء.
3. **أرقام سريعة**: الوحدات والمنشورة منها، الإقامات النشطة، العقود، الصور.
4. **الحجوزات اليومية، والعقود والإيجارات، والوحدات** (السعر، حالة النشر، الإشغال)، وبجانبها «يحتاج انتباهك» والمالية.
5. **إجراءات حساسة** في الأسفل: أرشفة/استعادة وحذف نهائي.

التفاصيل: [implementation/RELEASE-0.4.97-AR.md](./implementation/RELEASE-0.4.97-AR.md).

### 4.2 الظهور في الرئيسية

- Listing يظهر فقط إذا: منشور + عقار/وحدة فعّالان + الحالة `available` + ضمن نافذة النشر.
- حالات `held`, `reserved`, `leased`, `maintenance` تختفي من نتائج البحث آلياً.
- الرابط المباشر لوحدة غير متاحة يعرض صفحة مختصرة `noindex` بأقل بيانات ممكنة.

### 4.3 العقود والتوقيع

1. بعد الحجز/الطلب يُنشأ عقد بإصدار ثابت (versioned).
2. يُوقَّع إلكترونياً عبر OTP / إعادة مصادقة + Evidence Envelope وPDF hash.
3. عند اكتمال التوقيع يُفعَّل الـ Lease وتبدأ الفوترة.

### 4.3.1 الحجز بالعربون وشروط المالك (0.4.89)

- من صفحة الوحدة: «أريد التأجير» / «أريد الشراء» ← الشروط ← بياناتك ← المراجعة ← دفع العربون عبر BHD Pay ← توقيع العقد مع صور الهوية والصورة الشخصية ← التأكيد.
- المالك يكتب الشروط والأحكام لكل عقار (بيع / إيجار شهري-سنوي / إيجار يومي) من «الشروط والأحكام للعقود» في إدارة العقار، مع إصدارات محفوظة.
- العميل لا يرى مربع الموافقة إلا بعد التمرير إلى آخر الشروط، والنص الذي وافق عليه يُحفظ في الحجز ويُطبع في العقد.
- «هل الحجز لك؟»: جلب بيانات المستخدم تلقائياً، أو الحجز لشخص آخر مع حفظه في ملف المستخدم لاختياره لاحقاً.
- التفاصيل: [implementation/RELEASE-0.4.89-AR.md](./implementation/RELEASE-0.4.89-AR.md).

### 4.3.2 الإيجار اليومي: الحجز والتقويم (0.4.94 – 0.5.6)

#### صفحة حجز الإقامة اليومية (0.4.94)

- الصفحة `/stays/[slug]/book` بنفس تصميم صفحة حجز الإيجار/الشراء: صورة أصغر ونموذج بيانات أكبر.
- العنوان «احجز إقامتك القادمة» مع شرح بأربع خطوات:
  1. اختيار التواريخ ونوع الإقامة؛
  2. إدخال بياناتك؛
  3. المراجعة والموافقة على الشروط؛
  4. الدفع والتوقيع.
- عبارة «ابدأ إجراءات الحجز الآن» مع سهم يشير إلى النموذج، وزر تبديل اللغة يحافظ على التواريخ والوحدة وعدد الضيوف.
- خطوة «بياناتك»: سؤال «هل الحجز لك؟»:
  - «نعم، الحجز لي»: تُجلب بيانات المستخدم تلقائياً؛
  - «لا، لشخص آخر»: اختيار شخص محفوظ أو إضافة شخص جديد، مع خيار حفظه في الملف لاستخدامه لاحقاً.
- الحجز يحفظ لمن هو (`bookingFor`) ومن قام به (`bookedBy`)، والعقد يعرض «تم الحجز بواسطة» عند الحجز لشخص آخر.
- حفظ الشخص يتم عبر `POST /api/public/booking-contacts` بعد إنشاء الحجز، وفشل الحفظ لا يوقف الحجز.
- التفاصيل: [implementation/RELEASE-0.4.94-AR.md](./implementation/RELEASE-0.4.94-AR.md).

#### الحجز الكلي والجزئي في التقويم (0.4.95)

- اليوم يُقسم إلى فترتين:
  - **الصباحية (ص)** = إقامة بدون مبيت؛
  - **المسائية (م)** = مبيت فقط.
- اليوم المحجوز **كلياً** يظهر محجوزاً بالكامل. اليوم المحجوز **جزئياً** (فترة واحدة) يظهر بلونين، مع شارتي «ص» و«م»: ✓ للفترة الشاغرة و✗ للمحجوزة، ومعهما **سعر الفترة المتبقية**.
- سعر الفترة المتبقية هو السعر الذي ضبطه المالك لتلك الفترة، وإن لم يضبطه فسعر الليلة.
- الضغط على اليوم الجزئي في صفحة العقار يختار الفترة الشاغرة فقط وينقلها لصفحة الحجز.
- يظهر ذلك في: صفحة العقار العامة، وتقويم المالك، وصفحة تفاصيل الحجز للمالك (صف «نطاق الحجز» وحالة الفترة الأخرى وسعرها).
- دليل التقويم يشرح الرموز: ص، م، ✓، ✗، والسعر.
- التفاصيل: [implementation/RELEASE-0.4.95-AR.md](./implementation/RELEASE-0.4.95-AR.md).

#### سرعة التقويم وتقويم المالك الموحّد (0.4.96)

- **السرعة:** كان التقويم يتأخر حتى ~20 ثانية لأن دوال الموقع كانت تعمل في واشنطن وقاعدة البيانات في لندن. نُقلت الدوال إلى لندن (`lhr1`):

  | القياس | قبل | بعد |
  |---|---|---|
  | طلب التقويم | ~1.9 ثانية | ~0.3 ثانية |
  | صفحة العقار | ~4 ثوانٍ | ~1.6 ثانية |
  | ظهور التقويم في المتصفح | ~9 ثوانٍ | ~3 ثوانٍ |

- **تقويم المالك/المطوّر** (`/owner/stays/calendar` و`/developer/stays/calendar`):
  - يعرض كل العقارات في تقويم واحد بشكل افتراضي؛
  - **الأحمر** = يوم فيه حجوزات (مع عددها)، **الأخضر** = يوم شاغر؛
  - الضغط على التاريخ يعرض حجوزات ذلك اليوم: العقار والوحدة، الضيف، الهاتف، الفترة، التواريخ، المبلغ، الحالة، المرجع، ورابط تفاصيل الحجز؛
  - قائمة منسدلة للعقارات مع بحث بالاسم أو الرمز؛ اختيار عقار يعرض حجوزاته فقط، ويُظهر أسفله «الأسعار وإغلاق الأيام» لتعديل السعر وإغلاق الأيام.
- التفاصيل: [implementation/RELEASE-0.4.96-AR.md](./implementation/RELEASE-0.4.96-AR.md).

#### مبلغ التأجير وعدد الضيوف وبيانات البطاقة (0.4.98)

- الخطوة 1 «الإقامة» تعرض بطاقة «مبلغ التأجير» تتحدث تلقائياً حسب التواريخ ونوع الإقامة وعدد الضيوف:
  - السعر الأساسي، والإيجار، ورسوم التنظيف، والإجمالي؛
  - ✓ متاح أو ✗ مع السبب.
- السعر يأتي من الخادم (`GET /api/public/stays/[slug]/availability` يعيد `estimate`) بنفس طريقة عرض السعر النهائي، دون إنشاء سجل.
- عدد البالغين والأطفال:
  - أرقام 1–9؛
  - ثم فئات «≥ 10 و < 20» حتى «≥ 90 و < 100»، وكل فئة تملأ أول رقم فيها ويمكن تعديله؛
  - ثم «≥ 100» مع إدخال العدد الإجمالي إلزامياً.
- الحد الأقصى للضيوف في النظام 999، والحد الفعلي لكل عقار يضبطه المالك.
- صفحة الدفع التجريبية: النص التوضيحي في مربعات بيانات البطاقة أصبح شفافاً حتى لا يبدو كبيانات مُدخلة.
- التفاصيل: [implementation/RELEASE-0.4.98-AR.md](./implementation/RELEASE-0.4.98-AR.md).

#### تعديل بيانات الإيجار اليومي من صفحة تعديل العقار (0.4.99)

- لوحة «إعدادات الإيجار اليومي» في آخر الخطوة 2 «الوحدات»، ببطاقة لكل وحدة لها إعداد إقامة يومية:
  - الضيوف والمدة: الحد الأقصى للضيوف في المبيت وبدون مبيت (حتى 999)، والحد الأدنى والأقصى لليالي؛

  - الأسعار: الليلة، ونهاية الأسبوع، وبدون مبيت، والمبيت فقط، ومبلغ التأمين.
- كل بطاقة تُحفظ مستقلة عبر `POST /api/owner/stays/setup`، مع رابط للإعدادات المتقدمة (السياسات والتعليمات والنشر).
- إصلاح: صفحة التعديل أصبحت تقرأ `units.offering_modes`، فلا تتحول الوحدات اليومية إلى «إيجار شهري» عند الحفظ.
- التفاصيل: [implementation/RELEASE-0.4.99-AR.md](./implementation/RELEASE-0.4.99-AR.md).

#### شاشات الإقامات اليومية للمالك والمطوّر (0.5.0)

- شريط ثابت موحّد أعلى الشاشات الأربع: لوحة الإقامات، التقويم، الحجوزات اليومية، الأسعار والعروض، وزر «إضافة إقامة يومية».
- **لوحة الإقامات** (`/owner/stays`):
  - حركة اليوم بتوقيت مسقط (وصول، مغادرة، قادمة، تحتاج إجراء)؛
  - الحجوزات القادمة؛
  - الوحدات بأسعارها وحالة نشرها مع روابط التقويم والأسعار؛
  - أداء آخر 30 يوماً وملخص الحجوزات.
- **التقويم** (`/owner/stays/calendar`):
  - بطاقة واحدة متناسقة مع الشاشة؛
  - عند اختيار وحدة: زرّا «الحجوزات» و«الأسعار وإغلاق الأيام»؛
  - روابط `?unitId=` و`&view=prices`.
- **الأسعار والعروض** (`/owner/stays/rates`): كل الوحدات حسب العقار بأسعارها (الليلة، نهاية الأسبوع، بدون مبيت، مبيت فقط، التأمين) مع تعديل وحفظ في مكانها.
- **الحجوزات اليومية** (`/owner/bookings?tab=daily`):
  - دون أقسام الإيجار الشهري ودون بحث مكرر؛
  - بطاقات الأرقام هي أزرار التصفية.
- التفاصيل: [implementation/RELEASE-0.5.0-AR.md](./implementation/RELEASE-0.5.0-AR.md).

#### تواريخ الإقامة مع المبيت في صفحة الحجز (0.5.1)

- في `/stays/[slug]/book`، نوع «إقامة مع مبيت (يوم كامل)»:
  - الوصول افتراضياً هو تاريخ اليوم بتوقيت مسقط، والمغادرة هي الغد؛
  - التاريخ القادم الصالح في الرابط يُحترم، أما الماضي فيُستبدل بتاريخ اليوم.
- الضيف يغيّر التاريخين يدوياً، أو يمدّد ويقصّر بعدّاد الليالي (− / +) حتى 90 ليلة.
- تصحيح تلقائي للمغادرة لتكون بعد الوصول دائماً. «بدون مبيت» و«مبيت فقط» تبقى في يوم واحد.
- التفاصيل: [implementation/RELEASE-0.5.1-AR.md](./implementation/RELEASE-0.5.1-AR.md).

#### سرعة تحديث المبلغ في صفحة الحجز (0.5.2)

- **ذاكرة مؤقتة في المتصفح:** تقدير المبلغ (`/api/public/stays/[slug]/availability`) يُحفظ لمدة دقيقة، مع منع الطلبات المكررة.
- **جلب مسبق:** مبلغ ليلة وليلتين إضافيتين وليلة أقل يُجلب في الخلفية، فيتحدث المبلغ فوراً عند + / −.
- **بدون وميض:** المبلغ السابق يبقى ظاهراً أثناء التحديث، والمربع لا يتغير حجمه.
- **الخادم:** حساب السعر والتوافر بالتوازي.
- **السعر النهائي:** خطوة المراجعة تتحقق من الخادم مباشرة دون الذاكرة المؤقتة.
- التفاصيل: [implementation/RELEASE-0.5.2-AR.md](./implementation/RELEASE-0.5.2-AR.md).

#### تصميم صفحة الحجز (0.5.3)

- **الهيكل:** `.stay-book`، بطاقة عقار مصوّرة مع نموذج الحجز.
  - **على الشاشات الكبيرة:** البطاقة على الجانب وثابتة أثناء التمرير، بزوايا دائرية.
  - **على الجوال:** صورة علوية يتداخل معها النموذج.
- **بطاقة العقار تعرض:** الاسم، والموقع، والمزايا (الغرف، دورات المياه، الضيوف، المساحة)، والسعر من / الليلة، والتقييم، وأوقات الوصول والمغادرة.
- **خطوة «الإقامة»** في ثلاثة أقسام:
  - نوع الإقامة: بطاقات اختيار بأسعارها من `offer`؛
  - التواريخ: مربع واحد وعدّاد مدة؛
  - الضيوف.
- **لون رئيسي واحد** بدل الحدود الملوّنة المتعددة.
- **صفحة حجز الإيجار الشهري** (`/book/[unitId]`) ما زالت على `.stays-book-shell`.
- التفاصيل: [implementation/RELEASE-0.5.3-AR.md](./implementation/RELEASE-0.5.3-AR.md).

#### الدفع الفوري ورسائل الدفع (0.5.4)

- **حجز الإقامة من الموقع فوري دائماً:** يُنشأ بحالة `payment_pending` ويُحوَّل الضيف إلى الدفع مباشرة، بغض النظر عن `instant_book`.
  - السبب: لا يوجد بعد انتقال اعتماد من المالك (`request_pending` إلى `payment_pending`)، فكان حجز «طلب الحجز» لا يُدفع أبداً.
- **رسائل الدفع حسب رمز الخطأ** (`paymentErrorMessage` في `stay-checkout.tsx`) بدل اعتبار كل خطأ 409 «بوابة غير مفعّلة».
- **إعدادات المالك:** خانة «حجز فوري» استُبدلت بملاحظة؛ القيمة المخزّنة باقية لنظام موافقة مستقبلي.
- التفاصيل: [implementation/RELEASE-0.5.4-AR.md](./implementation/RELEASE-0.5.4-AR.md).

#### صورة أصغر وحقول أكبر في صفحة الحجز (0.5.5)

- **الصورة:** على الشاشات الكبيرة عمود أضيق `clamp(19rem, 30vw, 26rem)` وارتفاع حتى 36rem؛ على الجوال 13–15rem، ويُخفى شريط الأوقات تحت 600px.
- **النموذج:** بطاقة حتى 48rem، وحقول 3.4rem بخط 1.05rem، وبطاقات نوع الإقامة وأزرار المدة وزر المتابعة أكبر.
- التفاصيل: [implementation/RELEASE-0.5.5-AR.md](./implementation/RELEASE-0.5.5-AR.md).

#### بطاقة ملخّص الإقامة في صفحة الحجز (0.5.6)

- **البنية:** `.stay-book__bar` (شريط علوي: العودة، الشعار، اللغة) ثم `.stay-book__layout` بمنطقتين `summary` و`panel`، وحاوية بعرض أقصى 76rem.
- **البطاقة** `.stay-book__summary`: الصورة `.stay-book__media`، والتفاصيل `.stay-book__info`، والأوقات والثقة `.stay-book__extra`.
- **الشاشات الكبيرة (1000px فأكثر):** النموذج ثم البطاقة بجانبه (20–23.5rem)، والصورة 16:10، والبطاقة ثابتة أثناء التمرير.
- **أقل من 1000px:** بطاقة أفقية فوق النموذج بصورة جانبية (6.5–11rem).
- حلّت محل الصورة الخلفية القديمة `.stay-book__hero*`.
- التفاصيل: [implementation/RELEASE-0.5.6-AR.md](./implementation/RELEASE-0.5.6-AR.md).

### 4.4 تفعيل المستأجر

- النظام يمنح **اسم مستخدم** + **رابط/رمز تفعيل أحادي الاستخدام** داخل BHD Identity.
- لا تُرسل كلمة مرور دائمة بالبريد (قرار أمني معتمد).
- بعد التفعيل يدخل المستأجر لوحته فقط.

### 4.5 الممثلون والمشرفون

- المالك (فرد أو شركة) يعين مشرفين/ممثلين ضمن حدود الباقة (`entitlements`) وresource grants.
- كل ممثل يرى فقط الموارد الممنوحة له.

### 4.6 المالية والصيانة والتقارير

- فواتير بترقيم متزامن لكل مؤسسة/سنة، ومبالغ Decimal.
- مدفوعات مع `Idempotency-Key` وwebhooks موقّعة وunique `(provider, event_id)`.
- صيانة: بلاغ → تعيين → تقدم → إغلاق.
- تقارير من بيانات حقيقية عبر وحدة `reports` (ليست محاكاة).

## 6. نموذج البيانات (ملخص)

كيانات محورية:

| الكيان                           | الدور                               |

| `units`                          | وحدة first-class دائماً             |

| `listings`                       | سياسة الظهور العام                  |

| `contracts` / signatures         | عقد ونسخ وتوقيع                     |
| `leases`                         | إيجار فعّال                         |
| `invoices` / `payments`          | فوترة وتحصيل                        |
| `maintenance_requests`           | صيانة                               |
| `audit_events` / `outbox_events` | تدقيق وأحداث                        |
| `country_packs` / `currencies`   | التوسع الدولي                       |

**قواعد ملكية:**

- كل استعلام مؤسسي يحمل `organization_id`.

## 9. الأمن — ماذا أُغلق في BHD R؟

انظر المصفوفة الكاملة: [`SECURITY_CHECKLIST_MATRIX_AR.md`](./SECURITY_CHECKLIST_MATRIX_AR.md).

- Idempotency للمدفوعات والعمليات الحساسة + unique webhook events.
- فواتير عامة بـ opaque token وحقول مُقلَّلة.
