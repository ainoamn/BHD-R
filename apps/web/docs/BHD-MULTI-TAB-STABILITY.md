# استقرار تعدد الحسابات / التبويبات

> **آخر تحديث:** 1 نوفمبر 2026  
> **المشكلة:** وميض الصفحات، وتبدّل الحساب لحظياً بين تبويبين، وتحديث LiveSync لبيانات الحساب الخطأ، وظهور حساب خاطئ لثوانٍ عند تحديث الصفحة.

## السبب

كوكي جلسة المنتج مشترك بين تبويبات نفس الموقع. عند تحديث تبويب بـ `?au=A` بينما الكوكي لـ `B`، الـ SSR يرسم حساب B ثم الإصلاح الصامت يصحّح — وهذا وميض غير آمن.

## الإصلاح

1. **ممنوع** `location.replace` بعد إصلاح JSON صامت — الكوكي يُحدَّث مكانه فقط.
2. **التبويب المركّز الظاهر فقط** يكتب كوكي المنتج (`tabMayClaimProductCookie`).
3. بعد إصلاح فعلي: `bhd:account-rebound` → `router.refresh()` ناعم — **مع الإبقاء على غطاء الخصوصية** حتى يتأكد `/api/auth/me` أن `currentSub === ?au=`.
4. تهدئة أطول (45–60 ثانية) بين محاولات الإصلاح.
5. الإبقاء على `?au=` عبر `history.replaceState`.
6. **BroadcastChannel** `bhd-product-session` + `localStorage bhd_product_cookie_sub`: عند تبديل حساب تُعلَم باقي التبويبات ويُحفظ مالك الكوكي عبر التحديث.
7. **Bootstrap قبل الرسم:** إن وُجد `?au=` ومالك الكوكي المتذكَّر مختلف (أو مجهول) → `data-bhd-switching` فوراً؛ CSS يغطي الصفحة حتى التأكيد.
8. LiveSync يتجمّد عند كوكي معادٍ (`hasHostileProductCookie`).
9. قائمة الحساب تفضّل `readActiveAu()` على كوكي المنتج.

## التبديل الصريح

تبديل الحساب من القائمة: غطاء فارغ + hard rebind لهذا التبويب — مقصود. التبويبات الأخرى تبقى على `?au=` (مغطاة إن لزم) حتى يُركَّز عليها ثم تُصلح بصمت.

## إدارة الحساب على الهوية

انظر `BHD-MANAGE-ACCOUNT-AU.md` — الرابط يجب أن يستخدم `/auth/switch?sub=`.
